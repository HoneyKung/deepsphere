# ลำดับงานและเกณฑ์ส่งมอบ

สถานการณ์: อุปกรณ์เพิ่งมาถึงวันพฤหัส 10 กันยายน 2026 ผู้ใช้ประกอบฮาร์ดแวร์เอง ไม่มีข้อมูลเวลาส่งงานที่เหลือแน่นอน จึงใช้จุดตรวจตามผลลัพธ์แทนยกตารางอังคาร–พุธที่ผ่านไปแล้วมาใช้

## ผู้รับผิดชอบ

| คน | งาน |
|---|---|
| Astra | วางระบบ เขียนใบสั่งงาน ตรวจผลและตัดสินใจเรื่องขอบเขต |
| ผู้ใช้ | โครง 3D การต่อสาย จ่ายไฟ แฟลชและสังเกตชิ้นงานจริง |
| 5.6 Luna | เฟิร์มแวร์ เครื่องมือสร้าง/แปลงภาพ แผงควบคุมเรือดำน้ำพร้อมเสียง และคู่มือรัน |
| Claude Code | หาและเตรียมเสียงใหม่ตามใบสั่งงาน ช่วยตรวจข้อสงสัยเฉพาะจุดเมื่อได้รับมอบหมาย |

ผู้เขียนโค้ดมีสิทธิ์แก้ใน `prototype-v1/` ผู้หาเสียงแก้เฉพาะ `assets/audio/` กับเอกสารที่กำหนด ไม่ให้ทั้งสองคนแก้ไฟล์เดียวกันโดยไม่ตกลง

## จุดตรวจตามลำดับ

### G0 — โครงการ build ได้และรู้สถานะบอร์ด

- โค้ดใหม่ ไม่มี dependency หรือ asset จากเดโมเก่า
- มีคำสั่งติดตั้ง build flash และเลือก serial port ที่ทดสอบแล้ว
- รายงานชนิดบอร์ด Flash/PSRAM ที่ตรวจได้จริง และมี pin map ให้ผู้ใช้ดู
- ขาที่ยังไม่ยืนยันต้องระบุชัด โหมด hardware ต้องไม่ขับขาแบบสุ่ม; logic ที่ไม่ต้องมีบอร์ดเริ่มพัฒนาได้ทันที

### G1 — จอหนึ่งใบและภาพทดสอบถูกต้อง

- แสดงหมายเลขจอ ลูกศรขึ้น สี RGB และมุมทั้งสี่ถูกต้อง
- ตรวจ offset, inversion, rotation ของโมดูลจริงก่อนทำหกใบ
- แสดงส่วนของ atlas ใหม่ได้หนึ่งหน้า ให้ผู้ใช้ยืนยันจากจอจริง

### G2 — ครบหกใบและชั้นทะเล

- แสดง `px/nx/py/ny/pz/nz` เพื่อระบุตำแหน่งสาย
- ทุกหน้าแมพจากภาพชั้นทะเลชุดเดียวกัน ไม่ใช่เปิดภาพเดียวกันหกสำเนา
- ล้อเปลี่ยนระดับภาพครบทุกหน้า เมื่อหยุดล้อทั้งชุดอยู่ระดับเดียวกัน
- หมุนแกนแล้วพื้นหลังในพิกัดแต่ละจอไม่เปลี่ยนเพราะ yaw

### G3 — เป้าเล็งและปุ่ม

- ล้อ KY-040 เปลี่ยนมุมหันได้ กดล้อสลับ depth/heading ได้ เป้าวิ่งข้ามจอตามเรขาคณิตและซ่อนในช่วงกรอบตามกติกา
- ไม่มีรอยเป้าเก่าค้าง ไม่มีการกระโดดผิดที่เมื่อมุมผ่าน 359→0
- Scan hit/miss ตรงกับภาพและไม่มี hit เมื่อเป้าอยู่ในกรอบ
- Collect/Analyze ทำงานหนึ่งครั้งต่อการกด ไม่ค้างการอ่านอินพุต
- ถ้าใช้มุมจำลอง ให้รายงานว่ายังไม่ผ่านการหมุนฮาร์ดแวร์จริง
- ต้นแบบนี้ไม่มีเซนเซอร์วัดการหมุนติดอยู่เลย จุดตรวจ "หมุนตัวลูกแล้วเป้าอยู่กับที่" จึงไม่อยู่ในขอบเขต ทดสอบไม่ได้ และต้องรายงานว่าไม่ได้ทดสอบ ไม่ใช่ว่าผ่าน

### G4 — แผงควบคุม ภาพที่เก็บ เสียง และเดโมรวม

- แผงคอมแสดงระดับและผล Scan; กด Collect แล้วมีภาพใหม่ในคลัง ภาพเดิมไม่เปลี่ยนเมื่อหมุนลูกหรือเปลี่ยนความลึก
- กด Analyze แล้วเปิดรายละเอียดตัวอย่างที่เลือกหรือชิ้นล่าสุด ตรวจ asset_pack ตรงกันและโหลดภาพที่เก็บกลับได้เมื่อเปิดแผงใหม่
- Receiver ในแผงเล่น loop ตามระดับและ one-shot ตาม Scan/Collect/Analyze ด้วยเสียงใหม่
- เสียบ USB หลังบอร์ดบูตแล้วก็อ่าน state ได้ ปิด receiver แล้วชิ้นงานยังทำงาน
- ทางจ่ายไฟขณะต่อโน้ตบุ๊กไม่ขนานแหล่งจ่ายโดยตรง และผู้ใช้ยืนยันว่าเปิดครบหกจอแล้วไม่รีเซ็ต
- อัดวิดีโอชุดจริงทันทีที่เล่นวงจรครบ เก็บ build/config ที่ใช้ในชุดนั้น

## งานที่ทำแยกกันได้

- ผู้ใช้ทำโครง/ต่อสาย ขณะ Luna เขียนการแมพและ renderer จากมุมจำลอง
- Claude หาเสียงตามชื่อ cue ขณะ Luna ทำ receiver โดยยังไม่มีเสียงครบ
- ภาพสีทดสอบและภาพทะเลแบบเรียบง่ายใช้ตรวจระบบได้ก่อนภาพตกแต่ง

ไม่ต้องรอเสียงครบเพื่อทำ G0–G3 และไม่ต้องรอประกอบลูกปิดทั้งชุดเพื่อทดสอบจอหกใบ

## หลักฐานที่ต้องรายงาน

แต่ละจุดตรวจระบุสั้น ๆ ว่า ผ่านอะไร ใช้ฮาร์ดแวร์จริงหรือจำลอง คำสั่ง/ไฟล์ที่ใช้ และยังติดอะไร ไม่รายงานว่า “ทดสอบแล้ว” จากการอ่านโค้ดอย่างเดียว

เมื่อไม่มีเวลาพอ ให้ส่งเวอร์ชันล่าสุดที่ผ่านจริงพร้อมรายการค้าง ไม่ลดหกจอ เปลี่ยนเป้า หรือเปลี่ยนวิธีควบคุมเงียบ ๆ ลดเอฟเฟกต์ตกแต่งและแอนิเมชันก่อน การย้ายมุมหันไปอยู่บนล้อเป็นการเปลี่ยนวิธีควบคุมที่ผู้ใช้สั่งเอง และบันทึกไว้ในแผนระบบหัวข้อ 4 แล้ว ไม่ใช่การเปลี่ยนเงียบ

## ลำดับเมื่อพบปัญหา

1. Build/flash/pin map ผิด: แก้ก่อนงานภาพสวย
2. สีผิด/จอเพี้ยน: กลับ pattern จอเดียว ตรวจสาย/ไฟกับผู้ใช้ และลด SPI เพื่อแยกสาเหตุ
3. แมพภาพหรือเป้าผิด: ใช้ภาพ grid พร้อมเลขทิศและมุมจำลอง แยกจากเซนเซอร์
4. หน่วยความจำไม่พอ: ลดขนาด atlas และตารางช่วยคำนวณ รักษา semantics ของฉาก/เป้าไว้
5. เสียงไม่พร้อม: G0–G3 และงานแผงภาพเดินต่อ Receiver รายงานเสียงที่ขาด ไม่ย้อนกลับไปใช้เสียงเก่า

## เรื่องที่รอข้อมูล แต่ไม่ขวางการเริ่มโค้ด

- ยืนยันแล้ว: ปุ่ม Scan / Collect / Analyze และภาพเก็บแสดงบนแผงคอม ไม่ต้องรอถามเรื่องนี้อีก
- ยืนยันแล้ว: ไม่มีทั้งตัว AS5600 และแม่เหล็ก จึงไม่มีการอ่านการหมุนตัวลูกในต้นแบบนี้ ล้อรับหน้าที่ทั้งความลึกและมุมหัน โดยกดล้อเพื่อสลับ
- ผังสายที่ผู้ใช้ต่อไว้แล้ว และการยืนยันว่า GPIO6 ใช้เป็นสวิตช์ของล้อได้
- เวลาเดโม/ส่งจริงที่เหลือในวันนี้
- หมายเลขจอและขอบเขตช่องภาพจริงจากชิ้น 3D สำหรับปรับ config
