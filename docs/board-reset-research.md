# ทำไมบอร์ด ESP32-S3-Zero รีเซ็ต/หลุดเอง — สรุปจากเอกสาร (2026-10-27)

สถานะ: **อ่านเอกสารแล้ว ยังไม่ได้ทดสอบบนบอร์ด** ทุกข้อด้านล่างเป็นสมมติฐานจนกว่าจะวัด

## หลักฐานที่เราวัดเอง
- 2026-09-14 (ไม่ต่อจอ มีแค่ USB): ไม่มีโปรแกรมเปิดพอร์ต → Windows เห็นบอร์ดหาย/กลับมา 39 ครั้ง/66 วิ และ 93 ครั้ง/150 วิ (30–40 วิหลังแฟลช) · ทิ้งไว้ ~10 นาทีหลังแฟลช → 0 ครั้ง/180 วิ (แต่มีการเปิดพอร์ตค้าง 5 นาทีคั่น) · เปิดพอร์ตค้าง (DTR=1, RTS=0) → นิ่ง uptime ตรงนาฬิกา — `output/claude-usb-stability-status.md`
- 2026-09-17: uptime ~5 วิทุกครั้งที่เปิดพอร์ตใหม่ หาย 9 ครั้ง/40 วิ · reset_reason = unknown
- 2026-10-27: Windows ไม่เห็นบอร์ดเลย (ไม่มี COM, ไม่มี VID_303A)

## สิ่งที่เอกสารบอก (ตรวจกับไฟล์ในเครื่องแล้วบางข้อ)
1. **"unknown" ไม่ได้แปลว่าไม่รู้อะไรเลย** — framework ที่เราใช้คือ Arduino-ESP32 2.0.16 (`framework-arduinoespressif32` 3.20016.0 = ESP-IDF 4.4) ซึ่ง `esp_reset_reason()` แปลงรหัสรีเซ็ตจาก USB (0x15 USB_UART, 0x16 USB_JTAG) และไฟกระตุก (0x17 PWR_GLITCH) เป็น `ESP_RST_UNKNOWN` ทั้งหมด · ไฟตก (brownout) จะรายงานเป็น BROWNOUT ไม่ใช่ unknown · หัวงานตรวจแล้ว: รหัส 0x15/0x16/0x17 มีจริงใน `.platformio-core/packages/framework-arduinoespressif32/tools/sdk/esp32s3/include/soc/esp32s3/include/soc/reset_reasons.h:59-61` และไม่มี `ESP_RST_USB` ใน framework นี้ — ที่มา: esp-idf v4.4.7 `components/esp_system/port/soc/esp32s3/reset_reason.c`
2. **สาย RTS จากคอมรีเซ็ตชิปได้** — บน USB-Serial/JTAG "RTS ทำหน้าที่รีเซ็ตแกน" และไม่อ่านขา boot ใหม่ — https://docs.espressif.com/projects/esptool/en/latest/esp32s3/esptool/advanced-options.html · Windows ส่ง DTR ไปพร้อมตอนตั้ง RTS เท่านั้น (คอมเมนต์ใน esptool `reset.py` v4.7.0)
3. **หลังแฟลชแบบ `--after hard_reset` (ค่าเริ่ม) ชิปอาจค้างในโหมดดาวน์โหลด** เอกสารแนะนำ `--after watchdog_reset` (ลิงก์เดียวกับข้อ 2)
4. **ไฟ:** บอร์ดใช้ LDO ME6217C33M5G จ่ายสูงสุด 800 mA ไฟเข้า 5V ควรได้ ≥500 mA — https://www.waveshare.com/wiki/ESP32-S3-Zero · ไม่มีตัวเลขกระแสของจอ 1.3" ในเอกสาร Waveshare
5. **Windows selective suspend** เปิดเป็นค่าเริ่ม แต่ไม่มีเอกสารบอกว่าทำให้อุปกรณ์หลุด/ต่อใหม่
6. ไม่เจอเอกสารทางการว่า Windows เปิด/ปิดพอร์ตแล้วรีเซ็ตชิปเอง · issue ใกล้เคียง arduino-esp32 #11429 ปิดไปโดยไม่มีสาเหตุ

## สาเหตุเรียงจากน่าเป็นที่สุด (การอนุมาน ไม่ใช่ข้อเท็จจริง)
1. **ชิปถูกรีเซ็ตผ่าน USB (RTS/DTR จาก Windows)** — เข้ากับ "unknown", เกิดทั้งที่ไม่ต่อจอ, และนิ่งเมื่อมีโปรแกรมถือพอร์ตด้วย DTR=1 RTS=0
2. **สถานะค้างหลังแฟลชแบบ hard_reset** — เข้ากับที่หลุดถี่เฉพาะช่วงหลังแฟลช
3. **ไฟจอ 6 ใบจาก 3V3** — อธิบายรอบที่ไม่ต่อจอไม่ได้ แต่เกี่ยวกับตอนนี้ที่ต่อจอแล้วและจอติดแค่ 1 ใบ
4. Windows selective suspend — ไม่มีเอกสารรองรับ
5. สาย/หัวเสียบ — ตรวจก่อนสำหรับอาการ "Windows ไม่เห็นบอร์ดเลย" วันนี้

## วิธีแยกสาเหตุ (ถูก ไม่ต้องรื้อของ)
- ให้ firmware พิมพ์รหัสดิบ `rtc_get_reset_reason(0)` และ `(1)` ตอนเริ่ม: 0x15/0x16 = USB, 0x17 = ไฟกระตุก, 0x0F = ไฟตก, 0x01 = เปิดไฟใหม่ → แยกข้อ 1 กับ 3 ได้ทันที
- แฟลชด้วย `--after watchdog_reset` (หรือถอด-เสียบ USB หลังแฟลช) แล้วนับการหลุด 66 วิแบบไม่เปิดพอร์ตซ้ำ → ถ้าหายแปลว่าข้อ 2
- ถอดไฟ 3V3 ของจอออก เปลี่ยนสาย/พอร์ต ให้ Windows เห็นบอร์ดก่อน แล้วค่อยวัด 3V3 ตอนจอติดครบ
- ทดลองปิด USB selective suspend ใน Power Options (เปิดคืนได้)
