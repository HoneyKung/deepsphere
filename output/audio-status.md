สถานะ: ครบทั้งแปด cue สร้างไฟล์และตรวจด้วยเครื่องมือแล้ว **ยังไม่ผ่านการฟังด้วยหูมนุษย์**

## 1. ข้อจำกัดที่ต้องอ่านก่อน

ใบสั่งงานเขียนว่า "ฟังและคัดเองก่อนส่ง" และ "ไม่อ้างว่าฟังหรือประมวลผลแล้วถ้ายังไม่ได้ทำ"

**ผมฟังเสียงไม่ได้** ไม่มีหูและไม่มีทางรับรู้เสียงจริง สิ่งที่ทำแทนคือ **วัดค่าเชิงวัตถุ**
ของไฟล์ทุกไฟล์ แล้วคัดจากตัวเลข ไม่ได้คัดจากชื่อไฟล์ และไม่ได้ส่งแค่ลิงก์รายชื่อ

ค่าที่วัดต่อไฟล์: ความยาว, sample rate, จำนวนช่อง, peak/RMS/crest, DC offset, การ clip,
การกระจายพลังงานหกย่านความถี่, spectral centroid, spectral flatness, ความถี่หลักและความเป็นฮาร์มอนิก,
รูปซอง (attack / decay / จำนวน event), ความนิ่งของระดับ, ความต่อเนื่องที่รอยต่อ loop

ตัวเลขบอกได้ว่าเสียง "สว่างหรือมืด" "เป็นโทนหรือเป็นนอยส์" "สั้นคมหรือมีหาง" "ดังโดดหรือกลมกลืน"
ตัวเลข **บอกไม่ได้** ว่าเสียงนั้นน่าฟังไหม เข้ากับภาพไหม หรือฟังแล้วรำคาญไหม
ข้อนั้นต้องให้ผู้ใช้ตัดสิน ดูรายการที่ต้องฟังเองในหัวข้อ 7

## 3. เสียงที่เลือกและเหตุผล

### One-shot

| cue | ต้นฉบับ | ทำไมเลือก (จากค่าที่วัด) |
|---|---|---|
| `scan_hit` | Kenney `question_003.ogg` | โทนสว่าง ความถี่หลัก 2637 Hz ฮาร์มอนิก 0.61 ขึ้น 39 ms ตกถึง -20 dB ใน 194 ms มีหางสั้นแบบ ping |
| `scan_miss` | Kenney `question_004.ogg` | **ซองเสียงเท่ากับ hit เป๊ะ** แต่ความถี่หลัก 492 Hz และฮาร์มอนิก 0.98 (เกือบไซน์เปล่า) จึงเบากว่าและทึบกว่า hit ตามที่ใบสั่งงานขอ เป็นคู่ที่มาจากชุดสังเคราะห์เดียวกัน |
| `collect_success` | Kenney `confirmation_004.ogg` | สองโทนไล่ขึ้น ฮาร์มอนิก 0.74 ขึ้น 149 ms อ่านเป็น "เครื่องมือยืนยันว่าบันทึกแล้ว" ไม่ใช่บี๊บเปล่า |
| `analyze_open` | OwlishMedia `UI/UI_020.wav` | 6 event ต่อเนื่องในคลิปเดียว ฮาร์มอนิก 0.88 เป็นลำดับอ่านค่าแบบเครื่องมือ ไม่ใช่บลิปเดียวจบ เหมาะกับการเปิดแผงข้อมูล |
| `action_error` | Kenney `minimize_008.ogg` | สอง event สั้น ศูนย์กลางความถี่ 355 Hz และ **มีพลังงานย่าน 1-4 kHz เท่ากับ 0%** จึงได้ยินชัดแต่ไม่แหลมบาด ตรงกับ "เบาและไม่รบกวน" |

สี่ในห้า cue มาจากแพ็กเดียวกัน (Kenney Interface Sounds) เพื่อให้เสียงปุ่มเป็นชุดเดียวกัน
`analyze_open` มาจากอีกแพ็กโดยตั้งใจ เพราะเป็นเหตุการณ์ใหญ่กว่า (เปิดแผง) ไม่ใช่การกดปุ่ม

### Ambience

ทั้งสามชั้น **เป็นงานเรียบเรียงจากหลายแหล่ง ไม่ใช่คลิปเดียว** ตามที่ใบสั่งงานอนุญาตให้ทำ sound design
วัตถุดิบ: คลื่นทะเลจริง 8 คลิป (transitking, jasinski), เบดมหาสมุทรกรองต่ำ 2 ไฟล์ (gmason), ฟองอากาศ 2 ไฟล์ (BMacZero)

ไล่ระดับความมืดตามความลึกด้วย spectral centroid: **757 Hz -> 390 Hz -> 283 Hz**
รายละเอียดการกรอง การเร่งความเร็ว และระดับผสมของแต่ละชั้นอยู่ในช่อง `processing` ของ `catalog.json` ครบทุกขั้น

## 4. ข้อค้นพบที่เปลี่ยนวิธีออกแบบ: ลำโพงโน้ตบุ๊ก

เกณฑ์ผ่านของใบสั่งงานคือ "ทดสอบฟังจากโน้ตบุ๊กจริงได้" ลำโพงโน้ตบุ๊กทั่วไปตัดความถี่ต่ำกว่าราว 300 Hz ทิ้งเกือบหมด
ผมจึงวัดสัดส่วนพลังงานในย่าน 300 Hz - 8 kHz ของผู้สมัครทุกตัว ผลคือ:

- `underwater_or_space_engine_0.ogg` และ `deep_rumble.ogg` ของ gmason ซึ่งเป็นวัตถุดิบ ambience ที่ดีที่สุดที่หาได้
  มีพลังงานในย่านที่ลำโพงโน้ตบุ๊กเล่นได้ **0.0%** ทั้งคู่ (พลังงาน 97% และ 93% อยู่ต่ำกว่า 250 Hz)
  ถ้าใช้ตรง ๆ จะ **เงียบสนิทบนโน้ตบุ๊ก** แม้จะฟังดีมากบนหูฟัง
- Kenney `error_005` / `error_006` ที่ชื่อและลักษณะเหมาะกับ `action_error` ที่สุด ก็ตกด้วยเหตุผลเดียวกัน (4.0% และ 8.3%)

ทางแก้ที่ใช้: เร่งไฟล์ของ gmason ให้เร็วขึ้น 3 เท่า (และ 4 เท่าสำหรับ `deep_rumble`)
ซึ่งเลื่อนสเปกตรัมขึ้นราว 1.6 อ็อกเทฟ ทำให้ centroid ขยับจาก 129 Hz เป็น 389 Hz และเข้าสู่ย่านที่ได้ยิน
ตรวจแล้วว่าจังหวะคลื่นยังช้าตามธรรมชาติ (0.29 Hz หรือราว 3.4 วินาทีต่อลูก) ไม่กลายเป็นเสียงรัวถี่
และเลือก `minimize_008` แทน `error_005` สำหรับ `action_error`

ผลลัพธ์: ทั้งแปด cue มีพลังงานย่าน 300 Hz - 8 kHz ตั้งแต่ 42.6% ขึ้นไป

|---|---|---|---|---|---|---|

| `ambient_mid` | 26.00 s | -9.9 | -24.0 | 390 Hz | 68.8% | -8.0 |
| `ambient_deep` | 24.00 s | -10.9 | -24.0 | 283 Hz | 42.6% | -8.0 |
| `scan_hit` | 0.33 s | -3.0 | -12.1 | 2159 Hz | 100.0% | -12.3 |
| `scan_miss` | 0.33 s | -3.0 | -12.1 | 492 Hz | 100.0% | -12.3 |

ความยาวอยู่ในกรอบที่ใบสั่งงานกำหนดทุก cue (ambience 20-60 s, scan/collect/error 0.2-1.0 s, analyze 0.3-1.5 s)

### รอยต่อ loop

วิธีตรวจ: ต่อ loop กับตัวเองสองรอบ แล้วเทียบการกระโดดของระดับที่รอยต่อ กับการกระโดดที่เนื้อเสียงทำเองตามปกติ (เปอร์เซ็นไทล์ 99)
ถ้ารอยต่อไม่เกินความแปรปรวนปกติของเนื้อเสียง แปลว่าไม่โผล่เป็นตะเข็บ

| cue | step ที่รอยต่อ | กระโดดที่รอยต่อ | กระโดดปกติของเนื้อเสียง (p99) | ผล |
|---|---|---|---|---|
| `ambient_surface` | 0.000000 | 1.84 dB | 4.92 dB | ผ่าน |
| `ambient_mid` | 0.000000 | 0.76 dB | 6.70 dB | ผ่าน |
| `ambient_deep` | 0.000000 | 3.92 dB | 7.58 dB | ผ่าน |

### ทดสอบโหลดผ่านโค้ด receiver จริง

ไม่ได้ตรวจแค่ว่าไฟล์ decode ได้ แต่เรียก `AudioMixer` ใน `laptop/core.py` ของ Luna ตรง ๆ
ด้วย `catalog.json` ที่ส่งมา ผลคือ:

```
mixer settings: (44100, -16, 2)
cues loaded: 8 / 8
```

- mixer เจรจาได้ 44100 Hz / 16-bit / stereo **ตรงกับไฟล์ทุกไฟล์พอดี** จึงไม่มีการ resample ตอนเล่น
- ความยาวที่ pygame รายงานตรงกับที่ตั้งใจทุก cue (เช่น `ambient_surface` 30.000 s, `scan_hit` 0.332 s)
- `set_zone('surface')`, `set_zone('deep')` และ `play('scan_hit')` ทำงานผ่าน channel 0/1 ได้จริง

ข้อควรรู้: เครื่องนี้ติดตั้ง `pygame==2.6.1` ตาม `laptop/requirements.txt` ไม่ได้ เพราะยังไม่มี wheel
สำหรับ Python 3.14 และ build จาก source ไม่ผ่าน จึงติดตั้งและทดสอบด้วย `pygame-ce 2.5.8` (SDL 2.32.10) แทน
ซึ่งใช้ API `mixer.Sound` ชุดเดียวกัน **ไม่ใช่เวอร์ชันที่ pin ไว้** ถือเป็นการทดสอบตัวแทน
และไม่ได้แก้ `requirements.txt` ให้ ดูหัวข้อ 8

### การตั้งระดับ gain_db

`gain_db` เป็นค่าตั้งต้นที่คำนวณมา ไม่ได้เดา:

- ambience เล็งให้ RMS ตอนเล่นอยู่ที่ -32 dBFS ทั้งสามชั้นเขียนไฟล์ที่ระดับ RMS เท่ากัน (-24.0 dBFS) จึงได้ `gain_db` เท่ากันหมด สลับชั้นได้โดยระดับไม่กระโดด
- one-shot เล็งให้ช่วง 300 ms ที่ดังที่สุดอยู่ที่ -24 dBFS คือ **สูงกว่าพื้น ambience 8 dB** เพื่อให้เสียงปุ่มชัดโดยไม่ดังโดด
- ใช้ช่วง 300 ms ที่ดังที่สุดแทน RMS ทั้งไฟล์ เพราะ RMS ทั้งไฟล์จะประเมิน `analyze_open` ต่ำเกินจริง (เป็นเสียงหลาย event เว้นจังหวะ) แล้วดันให้ดังเกิน
- ผลคือ peak ตอนเล่นของ one-shot ทั้งห้าอยู่ในช่วงแคบ -15.3 ถึง -12.4 dBFS

## 7. สิ่งที่ยังค้าง ต้องให้ผู้ใช้ฟังเอง

เรียงตามความสำคัญ:

1. **ฟังทั้งแปดไฟล์บนโน้ตบุ๊กเครื่องจริง** ทั้งลำโพงในตัวและหูฟัง นี่คือเกณฑ์ผ่านที่ผมทำแทนไม่ได้
2. **`scan_miss` กับ `action_error` แยกออกจากกันไหม** ทั้งคู่เป็นโทนค่อนข้างต่ำ (492 Hz กับ 355 Hz)
   ตัวเลขบอกว่าต่างกัน (ไซน์เปล่า 1 event เทียบกับ 2 event ที่ฮาร์มอนิก 0.55) แต่ต้องยืนยันด้วยหู
   ถ้าสับสน บอกมาได้ ผมเปลี่ยน `action_error` เป็นตัวอื่นให้
3. **`ambient_deep` ยังได้ยินพอไหมบนลำโพงโน้ตบุ๊ก** ตั้งใจให้มืดที่สุด จึงเหลือพลังงานย่านที่ลำโพงเล่นได้ 42.6%
   ซึ่งต่ำสุดในสามชั้น ถ้าเบาไปให้บอก จะขยับฟิลเตอร์ขึ้น
4. **ลอง loop ทิ้งไว้ 2-3 นาทีต่อชั้น** ตัวเลขบอกว่ารอยต่อไม่โผล่ แต่ความรู้สึก "วนซ้ำจนน่าเบื่อ" วัดไม่ได้
   ถ้ารู้สึกซ้ำ เพิ่มความยาว loop ได้ (สคริปต์รับความยาวเป็นพารามิเตอร์)
5. **ลองผสม ambience กับ one-shot จริงในแผง** `gain_db` เป็นค่าตั้งต้นที่คำนวณมา ไม่ใช่ค่าที่ฟังแล้วปรับ
6. **`ambient_surface` ยังฟังเป็นชายหาดอยู่ไหม** วัตถุดิบเป็นคลื่นชายหาดจริง กรองยอดบนที่ 4.2 kHz
   และบีบยอดคลื่นลงแล้วเพื่อลดความเป็นชายหาด แต่ต้องยืนยันด้วยหูว่ากลายเป็น "ใต้น้ำใกล้ผิว" ได้จริง

## 8. ข้อสังเกตส่งต่อ Astra / Luna (ไม่ได้แก้สัญญาเอง)

**schema ของ catalog รองรับหนึ่งแหล่งต่อหนึ่ง cue** แต่ ambience ทั้งสามชั้นสร้างจาก 3-4 แหล่ง
ผมทำตาม schema เดิมทุก field ไม่เพิ่มไม่ลด โดยใส่แหล่งหลักใน `source_url` และไล่ชื่อผู้สร้างทุกคนใน
`creator` กับ `attribution` ส่วนรายละเอียดว่าแหล่งไหนถูกทำอะไรอยู่ใน `processing` ครบ

ถ้าจะแก้ schema รอบหน้า การเพิ่ม `sources` เป็น array จะตรงกับความจริงของ cue แบบเรียบเรียงมากกว่า
**แต่นี่เป็นข้อเสนอ ไม่ได้เปลี่ยนอะไรเอง** เพราะ catalog เป็นสัญญาร่วมกับฝั่ง receiver

อีกข้อ: ใบสั่งงานเขียนว่า `gain_db` "ไม่ได้บังคับ -12 dB ทุกเสียง" ค่าที่ส่งมาจึงต่างกันไปตามที่คำนวณได้จริง
(-12.3 ถึง -8.0) ฝั่ง receiver ควรอ่านค่าจาก catalog ไม่ใช่ hardcode

### ข้อสังเกตจากการอ่านโค้ด receiver (อ่านอย่างเดียว ไม่ได้แก้)

**1. `AudioMixer` ยังไม่ได้ใช้ `gain_db` เลย**

`laptop/core.py` อ่านจาก catalog เฉพาะ `cue["file"]` กับ `cue["cue_id"]` แล้วสร้าง `pygame.mixer.Sound`
โดยไม่เรียก `set_volume()` ที่ไหน ผลคือทุก cue เล่นที่ระดับในไฟล์ตรง ๆ และสมดุลที่ผมคำนวณไว้ยังไม่มีผล

ตัวเลขที่ต่างกัน: ถ้าใช้ `gain_db` เสียงปุ่มจะอยู่สูงกว่าพื้น ambience 8 dB ตามที่ตั้งใจ
ถ้าไม่ใช้ ระยะห่างจะกลายเป็นราว 12 dB และทั้งระบบดังขึ้นประมาณ 8 dB
ยังไม่ถึงขั้นพัง แต่เสียงปุ่มจะโดดกว่าที่ออกแบบไว้

จุดที่เกี่ยวข้องคือลูปโหลด cue ใน `AudioMixer.__init__` การเติม `set_volume(10 ** (cue["gain_db"] / 20))`
ตอนสร้าง `Sound` จะทำให้ค่าที่คำนวณมามีผล **ผมไม่ได้แก้ให้ เพราะ receiver เป็นงานของ Luna**

**2. `set_zone` ยังไม่ crossfade**

`docs/audio-protocol.md` เขียนว่า "Ambient crossfade เมื่อโซนเปลี่ยน" แต่ `set_zone` เรียก
`Channel(0).play(sound, loops=-1, fade_ms=500)` ซึ่ง fade in เสียงใหม่ ส่วนเสียงเดิมบนช่องเดียวกันหยุดทันที
เป็น fade in ด้านเดียว ไม่ใช่ crossfade สองด้าน ถ้าต้องการ crossfade จริงต้องใช้สองช่องสลับกัน
ข้อนี้อยู่ในขอบเขตของ Luna เช่นกัน ผมแค่รายงาน

**3. `pygame==2.6.1` ติดตั้งไม่ได้บน Python 3.14**

ไม่มี wheel และ build จาก source ล้มเหลวบนเครื่องนี้ ถ้าโน้ตบุ๊กที่ใช้เดโมเป็น Python 3.14
จะติดปัญหาเดียวกัน ทางเลือกคือใช้ Python 3.12/3.13 หรือเปลี่ยนไป `pygame-ce`
**ไม่ได้แก้ `laptop/requirements.txt` ให้** เพราะเป็นไฟล์ของฝั่ง implementation
