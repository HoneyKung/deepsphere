# ใบ 18 รอบแก้ 1 — ผู้ตรวจอิสระตัดสิน FIX FIRST (2026-10-28)

หัวงานเปิดโค้ดตรวจแล้ว ข้อ 1–4 เป็นจริงทุกข้อ ขอบเขตไฟล์และกฎทั้งหมดใช้ตามใบ LUNA-18 เดิม **ยกเว้นข้อที่ขยายด้านล่าง**
**ขยายขอบเขต (ใบเพิ่ม):** แก้ได้ทั้ง `loop()` และตัวอ่าน Serial ที่มีอยู่แล้วใน `panel_one.cpp` และ `demo_live_yaw.cpp` แต่แก้เฉพาะเพื่อเรียกใช้ตัวพิมพ์รีเซ็ตเท่านั้น

## ข้อ 1 — แย่งอ่าน Serial จาก task อีกตัว (`reset_probe.h:77-80`)
- task บน core 0 มาแย่งอ่านคิว RX เดียวกับ `loop()` ผลคือคีย์ `r` มักไม่ถูกจับ หรือไปขโมยตัว `r` ในคำสั่ง `as5600_zero` (`demo_live_yaw.cpp` `readCommands`/`handleCommand`)
- แก้: **ลบ task ทิ้ง** ห้ามอ่าน Serial ใน `reset_probe.h` · panel-one: ตัวอ่านคีย์เดิมรับ `r` เพิ่มเป็นคีย์เดี่ยว · live-yaw: `handleCommand` รับเฉพาะบรรทัดที่เป็น `r` ตรงตัวทั้งบรรทัด ห้ามดักทีละตัวอักษร

## ข้อ 2 — บรรทัดซ้อนกัน
- ตัวพิมพ์บน core 0 พิมพ์แทรกกลาง `sendYaw` ที่เรียก `Serial.print` หลายครั้งต่อหนึ่งบรรทัด (`demo_live_yaw.cpp:24-32`) บรรทัด yaw จึงเสีย
- แก้: เพิ่ม `resetProbeTick()` แล้วเรียกจาก `loop()` ของทั้งสองไฟล์ ให้พิมพ์ซ้ำทุก 2 วิ ใน 10 วิแรก ทุกการพิมพ์ต้องเกิดใน task เดียวกับที่ส่ง yaw และต้องไม่พิมพ์แทรกกลางบรรทัดอื่น

## ข้อ 3 — ชื่อฟังก์ชันชนกับ SDK
- SDK มี `rtc_get_reset_reason` อยู่แล้ว (`tools/sdk/esp32s3/include/esp_rom/include/esp32s3/rom/rtc.h:159`) ที่รายงานว่า "ไม่มี" จึงผิด ตัว wrapper ใน `reset_probe.h:9` ไปบังชื่อของ SDK
- แก้: ใช้ของ SDK ตรง ๆ (`#include <esp32s3/rom/rtc.h>`) หรือเปลี่ยนชื่อ wrapper เป็นของเราเอง แล้วแก้ข้อความนี้ในรายงานให้ถูก

## ข้อ 4 — MD5 อาจไม่ตรงกับซอร์สล่าสุด
- `panel_one.cpp` ถูกแก้ตอน 00:13:21 แต่ build ไปก่อนแล้วตอน 00:12:03 และ 00:12:36
- แก้: build ใหม่ทั้ง 4 env หลังแก้ครบทุกข้อ แล้วจด MD5 ใหม่

## ข้อ 5 (เล็ก) — `panel-one-noreset` พึ่งไลบรารีในเครื่อง
- ใช้ `lib_extra_dirs = .pio/libdeps/panel-one` ถ้าทำได้โดยไม่ต้องดาวน์โหลดอะไร ให้เปลี่ยนเป็น `extends` แบบปกติที่ใช้ `lib_deps` ร่วมกับ env หลัก ถ้าทำไม่ได้ ให้คงไว้แล้วเขียนเหตุผลลงรายงาน
