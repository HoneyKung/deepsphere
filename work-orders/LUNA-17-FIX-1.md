# ใบ 17 รอบแก้ 1 — ผู้ตรวจอิสระตัดสิน FIX FIRST (2026-10-28)

หัวงานตรวจเองแล้วว่าข้อ 1–3 เป็นจริง ส่วนข้อ 4 ให้ตรวจโค้ดก่อนแล้วค่อยแก้ ขอบเขตไฟล์และกฎทั้งหมดใช้ตามใบ LUNA-17 เดิม ห้ามแฟลช ห้ามดาวน์โหลด

## ข้อ 1 — เทสเดิมล้ม 2 ตัว (รายงานไม่ได้บอกเรื่องนี้)
- รัน `python -m unittest tests.test_config_agreement` ได้ 1 FAIL + 1 ERROR
  - `depth_step_norm` ถูกเปลี่ยนเป็น 0.0166666667 แต่ต้องตรงกับ `kDepthStepPerDetent` = 0.02 (`firmware/include/deep_sphere_config.h:103`)
  - ลบคีย์ `buttons.analyze_recommended_alternative` ไปแล้ว ทำให้เกิด KeyError ที่ `tests/test_config_agreement.py:77`
- แก้: คืนคีย์และค่าเดิมของบอร์ดหมุนใน `config/controls.json` ให้ครบทุกตัว ส่วนค่าของบอร์ดฐานให้ใส่เป็นคีย์ใหม่ใต้หัวข้อใหม่ (เช่น `base_board`) ห้ามแก้เทสเดิม รันเทสนี้ต้องผ่านครบ 16/16

## ข้อ 2 — event เก่าถูกเล่นซ้ำ / event ใหม่หาย (`twin/twin.js:1338`, `laptop/twin_bridge.py:130`)
- หน้าเว็บเริ่มนับ cursor ที่ 0 พอ reload หน้าจะเล่น event เก่าซ้ำได้ถึง 256 ตัว ปุ่ม down เก่าจะสั่ง Scan/Collect/Analyze ซ้ำ ในทางกลับกัน ถ้า bridge รีสตาร์ต id จะเริ่มที่ 1 ใหม่ แต่ cursor ฝั่งหน้าเว็บยังค้างค่าสูงไว้ event ใหม่จึงหายเงียบ
- แก้: poll ครั้งแรกให้ตั้ง cursor = id ล่าสุดโดยไม่ทำ event ใด ๆ และให้ bridge ส่ง session id ไปด้วย (หรือถ้า id ล่าสุดน้อยกว่า cursor ให้ตั้ง cursor ใหม่โดยไม่ทำ event) · เพิ่มเทสทั้งสองกรณี

## ข้อ 3 — ข้อความที่ส่งมามี `id` แล้วไปทับเลขลำดับ (`twin_bridge.py:131,137`)
- แก้: เปลี่ยนเป็น `{**message, "id": seq}` ทั้งสองจุด แล้วเพิ่มเทส

## ข้อ 4 — ตอนเปิดพอร์ต อาจดึง GPIO0 ของบอร์ดฐานค้างไว้ที่ LOW (ตรวจก่อนแก้)
- ผู้ตรวจรายงานว่า `_open` ตั้ง `dtr=True, rts=False` ซึ่งบนวงจร auto-reset ของ DevKit จะดึง IO0 ลง LOW ถ้าบอร์ดรีเซ็ตตอนนั้น จะบูตเข้าโหมดดาวน์โหลด และ hello จะไม่ถูกส่งซ้ำ
- แก้: สำหรับพอร์ต VID 10C4/1A86 ให้ตั้ง DTR=False, RTS=False · พอร์ต S3 (303A) ให้คงค่าเดิมไว้ เพราะเป็นค่าที่พิสูจน์แล้ว · ให้ firmware ส่ง hello ซ้ำทุก 5 วินาทีด้วย (build ใหม่แล้วจด MD5)
