# LUNA-13: ใบรวม เสียงพากย์ + หน้าตาเว็บทวิน + สะพานบอร์ด (ต่อจาก LUNA-12)

ผู้สั่งงาน: Claude · ผู้ทำ: **Codex Luna หรือ Gemini** · วันที่: 2 ต.ค. 2026 · รันจาก `prototype-v1/`
ใบนี้รวมของที่ค้างทั้งหมดไว้ที่เดียว ทำตามลำดับ A → B → C จบแต่ละข้อเขียน 2–3 บรรทัดใน `output/luna-13-progress.md` (กันหมดโควตา) รายงานสุดท้ายที่ `output/luna-13-status.md`
**ขอบเขต:** `twin/`, `laptop/twin_bridge.py`, `assets/audio/` (เพิ่มได้เฉพาะ catalog/manifest ถ้าจำเป็น) · **ห้ามแตะ** เฟิร์มแวร์ pin map จอ 6 ใบ `config/scene.json` · **ห้ามแตะ** ไฟล์เสียงที่ Claude ทำแล้ว · ห้ามแฟลชบอร์ด

## 0. สถานะที่ Claude ตรวจแล้ว (2 ต.ค.)

- LUNA-12 เสร็จ ตรวจรับแล้ว (Web Audio 6 บัส, 77 cue) · Claude แก้เทสที่ล้มเพราะ `scan_miss.wav` เป็น mono แล้ว (แปลง 4 ไฟล์ของชุดเดิมเป็น stereo)
- **เสียงพากย์เปลี่ยนเป็นไฟล์แล้ว** ผู้หญิงภาษาอังกฤษ (ผู้ใช้เลือก "Michelle" หวาน เบาลม) `assets/audio/voice/vo_*_en.wav` 14 ไฟล์ + ชื่อสัตว์ 6 ไฟล์ `voice/vo_name_<shoal|reef|seahorse|manta|lantern|jelly>_en.wav` ลงทะเบียนใน `sound-manifest.json` ที่ `voice` และ `voice_names` แล้ว · **ไม่มีไฟล์ไทย** (เว็บสลับเป็นอังกฤษเองอยู่แล้ว ถูกต้อง) · ตรวจแล้วว่า `speakLine('vo_scan_hit')` เล่นเป็น FILE ผ่านบัส `voice` ไม่ใช่ speechSynthesis
- บอร์ด: เฟิร์มแวร์ `live-yaw` ถูกแฟลชแล้ว ส่งข้อมูลถูกรูปแบบ 25 Hz แต่ **เซนเซอร์ AS5600 ไม่ตอบ** (`ok:false, magnet:"missing"`) ผู้ใช้กำลังเช็กสาย เว็บโหมด `?live=1` ต้องรับมือกรณีนี้ได้เรียบร้อย
- มีสะพาน `twin_bridge.py` ของ Claude รันค้างอยู่ (ซ่อนหน้าต่าง) ถือ COM6 และพอร์ต 8765 ก่อนรันสะพานเอง ให้หยุดตัวนั้นก่อน: `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'twin_bridge' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }` (รอ ~3 วิ ให้พอร์ตว่าง)

## A. แก้เสียงพากย์ในเว็บ (ทำก่อน เล็ก แต่เห็นผลตอนโชว์)

1. **`vo_welcome` ไม่ถูกเล่นตอนกดเริ่ม:** ใน `start()` (twin.js ~บรรทัด 1013) สั่ง `speakLine('vo_welcome')` ด้วย timer 650 ms แต่ตอน Claude กด BEGIN EXPLORATION ในเบราว์เซอร์จริง แผงตรวจเสียงไม่มีบรรทัด `vo_welcome` เลย (ส่วนสั่งตรง ๆ `speakLine('vo_scan_hit')` ทำงานปกติ) หาสาเหตุ (เช่น token ชนกัน, เรียกก่อนโหลดบัฟเฟอร์, muted/voiceLanguage ตอนนั้น) แล้วแก้ ให้เล่นหลังเสียงปิดห้อง `dive_start` ราว 0.6–1 วิ และเพิ่มเทส/ตรวจด้วยเบราว์เซอร์
2. **แถบเลื่อนความดังพากย์แยกจากเสียงอื่น:** เพิ่ม slider "Voice" (0–100%, ค่าเริ่มต้น 100%) ทำงานกับบัส `voice` (คูณกับ `BUS_DEFAULTS.voice`) เก็บค่าใน localStorage (ห่อ try/catch) วางไว้ใน UI หลักข้างปุ่ม M (เล็ก ไม่รก) และในแผง `?audio=debug` · ปรับค่าตั้งต้นของบัส `voice` ให้ฟังชัดโดยไม่กลบเพลง: ไฟล์พากย์ RMS ≈ −21 dBFS ตอนนี้บัส 0.9 ให้ลองฟังจริงกับเพลง+ทะเล แล้วรายงานค่าที่เลือก
3. **`vo_analyze` พูดชื่อสัตว์:** เล่น `vo_analyze` ("Analysis complete.") ตามด้วยคลิปชื่อสัตว์ใน `manifest.voice_names[<key>]` ของทุกตัวในถาดตามลำดับที่เก็บ เว้น ~0.15 วิ (ใช้ duck ชุดเดียวต่อเนื่อง ไม่คืนระดับเพลงระหว่างคลิป) ถ้าไม่มีคลิปชื่อ ให้พูดแค่ประโยคหลัก
4. **ภาษาพากย์:** ค่าเริ่มต้นเป็น English เมื่อไม่มีไฟล์ไทย ตัวเลือกไทยให้ซ่อนหรือ disable พร้อมป้ายอธิบาย (ไม่ต้องลบโค้ดไทย เผื่อมีไฟล์ไทยในอนาคต)

## B. หน้าตาเว็บทวิน ให้เป็นโทนเดียวกับ Sound Map (งานหลัก)

ผู้ใช้ชอบสี/ตัวอักษร/โครง HUD ของอาร์ติแฟคต์ Sound Map มาก ไฟล์อ้างอิงอยู่ที่ **`assets/audio/soundmap-reference.html`** (ดู `<style>` ต้นไฟล์ และ `.scope`, `.hud-*`, `.zone`, `.subs`, `.mk`, `.key`, `.panel`) ให้เอา **ภาษาภาพ** มาใส่เว็บทวิน (`twin/index.html` + `twin/deepcore.css`)

**ทำ:**
1. **ธีมสี (แทนค่าใน `:root` ของ deepcore.css):** abyss `#050f15` (พื้น) · hull `#0b1b23` / `#10262f` / `#15313c` (แผง) · line `#1c3a45` / `#28505d` · ink `#d9e8ea` · ink-2 `#9db6bd` · ink-3 `#6c8790` · **brass `#d9b878` (หัวข้อ/ปุ่มหลัก)** · **sonar `#63d6cf` (เน้น)** · สีโซน: ตื้น `#7fd3e6`, กลาง `#63d6cf`, ลึก `#ff9f43` · ลดความฟ้านีออน (`#00d4ff`, `#00ffcc`) เดิมลง
2. **ฟอนต์:** แทน Orbitron/Inter ด้วย **Chakra Petch** (หัวข้อ ตัวเลข) + **IBM Plex Sans Thai** (เนื้อความ รองรับไทย) + IBM Plex Mono (ค่าตัวเลขเล็ก) จาก Google Fonts (ถ้าเปิดออฟไลน์ ต้องมี fallback ที่อ่านได้ ไม่พัง)
3. **HUD จัดตามอาร์ติแฟคต์:** ความลึกใหญ่มุมซ้ายบน + ชิปโซน ("ตื้น · SURFACE" / "กลาง · MID" / "ลึก · DEEP" ขอบสีตามโซน) · ค่าอ่านมุมขวาบน (ทิศ, แรงดัน, อุณหภูมิ, จอที่เล็ง) · ถาดตัวอย่าง "n / 6" · แถบความลึกมีเส้นแบ่งโซน 760/1,976 ม. · ปุ่ม Scan/Collect/Analyze/Highlight ทำเป็นปุ่มคีย์ (`kbd` chip) แบบ `.key`
4. **คำบรรยาย 2 ภาษา:** กล่อง narration แสดง **บรรทัดอังกฤษ (ตรงกับเสียงพากย์) + บรรทัดไทย** ของประโยคพากย์ทุกครั้งที่ `speakLine` เล่น ใช้ `VOICE_LINES[id].th` และ `.en` ที่มีอยู่แล้ว (`{names}` แทนด้วยชื่อสัตว์ที่พูด) ข้อความเดิมของ `say()` ที่ไม่ใช่พากย์ยังแสดงได้
5. **หน้าเริ่ม (intro):** ชื่อ DEEP SPHERE สีทอง ปุ่มเริ่มสีทอง พื้นไล่สีทะเลลึก ข้อความช่วยเป็นภาษาไทยสั้น ๆ ได้ ("ลากเพื่อหมุนกล่อง · ลูกศรคุมความลึกและทิศ · 1 สแกน 2 เก็บ 3 วิเคราะห์ · M ปิดเสียง")
6. **ป้ายเสียงลอย (ถ้ามีเวลา):** เมื่อเกิดเสียงสำคัญ (ข้ามโซน, สแกนเจอ, เก็บ, ค้นพบ, เตือน) ให้มีป้ายเม็ดยาวลอยขึ้นสั้น ๆ (animation 2.8 วิ) บอกชื่อเหตุการณ์เป็นภาษาไทย เหมือน `.mk` ในอาร์ติแฟคต์ ใช้ข้อมูลจาก `audioLog` ที่มีอยู่ (ปิดได้ด้วยปุ่มหรือ `?audio=debug` เท่านั้นที่เห็นแหล่งไฟล์/ร่าง)
7. คงปุ่มวิศวกรรมเดิม (Unfold, Two-face edge, Map grid, Seam fixture, yaw/depth input) ไว้ แต่จัดให้ดูเป็นแถบเครื่องมือรองที่ไม่แย่งสายตา (เช่น พับเก็บหรือโปร่งแสง)

**ห้าม/ระวัง:**
- **ห้ามเปลี่ยนตรรกะหรือผลลัพธ์ของ 3D** (`geometry.js`, `renderer.js`, ภาพบนจอ 6 ใบ, `panel-strip`, เป้าเล็ง) · ทำเฉพาะ DOM/CSS ของ HUD รอบ ๆ และธีมสีของเฟรม ไม่แก้สีปลา/ทะเลในแผงที่ตรงกับเฟิร์มแวร์
- เทสเดิมต้องผ่านเท่าเดิม (vectors ของ twin/geometry, browser checks ที่มีอยู่) ห้ามพังหลังแก้
- ตัวหนังสือไทยต้องไม่ล้นกรอบ ลองหน้าจอ 1366×768 (โน้ตบุ๊กที่ใช้โชว์) และ 1920×1080 · คอนทราสต์ตัวอักษรอ่านง่าย (≥ 4.5:1) · ขนาดตัวอักษรไม่ต่ำกว่า 12 px
- แคปภาพหน้าเว็บก่อน/หลังที่ 1366×768 ลง `output/luna-13/` (ก่อน, หลัง, หน้าเริ่ม, มีคำบรรยาย, หน้าลึก ชิปส้ม) ให้ผู้ใช้ตรวจ

## C. สะพานบอร์ด `laptop/twin_bridge.py` ต่อติดง่ายและบอกสาเหตุ (ถ้ามีเวลา)

ที่มา: ผู้ใช้เคยต่อได้ที่บ้านแต่ในคาบต่อไม่ติด และไม่มีใครรู้เหตุผลเพราะสะพานไม่เก็บ log
1. **หาพอร์ตเอง:** ถ้าไม่ระบุ `--port` ให้ค้นหาพอร์ตที่ `vid:pid = 303A:1001` (ESP32-S3 USB) ด้วย `serial.tools.list_ports` (ค่าเริ่มต้นตอนนี้ฮาร์ดโค้ด `COM6`) ถ้าเจอหลายตัวให้เลือกตัวแรกและพิมพ์บอก · `--port` ยังบังคับได้
2. **ลองต่อใหม่ทุก ~1 วินาที** เมื่อพอร์ตหายหรือเลขเปลี่ยน (ค้นหาใหม่ทุกรอบ) ไม่ต้องรีสตาร์ตสะพาน
3. **เหตุผลที่ต่อไม่ติดต้องเห็นได้:** ส่งใน `/yaw` เป็น `reason` ที่อ่านรู้เรื่อง ("port not found", "access denied (another program holds COMx)", "no data (wrong firmware?)", "sensor unavailable (AS5600 not responding)") และแสดงบนแถบ banner ของเว็บ (`setLiveBanner`) เป็นข้อความสั้น ๆ
4. **เขียน log ถาวร** ลง `output/twin-bridge.log` (เวลา, พอร์ต, เหตุการณ์ เปิด/ปิด/ผิดพลาด/จำนวน parse error) หมุนไฟล์เมื่อเกิน ~1 MB
5. **ตรวจเฟิร์มแวร์ผิดตัว:** ถ้าอ่านบรรทัดได้แต่ไม่ใช่ JSON ต่อเนื่อง (เช่น `panel_check:` ของเฟิร์มแวร์ `diag`) ให้บอกว่า "board is running diagnostic firmware, flash live-yaw" แทนการพิมพ์ "serial parse error" รัว ๆ (จำกัดความถี่ข้อความ)
6. เทสด้วย `--simulate` และด้วย mock serial (ไม่ต้องมีบอร์ด) · ห้ามเปิดพอร์ตค้างเกินจำเป็น และไม่เปลี่ยน DTR/RTS (ยังเป็น DTR=1 RTS=0 ตาม `SerialWorker`)
