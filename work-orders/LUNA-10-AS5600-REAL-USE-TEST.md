# LUNA-10: เทสตัวจับแม่เหล็ก AS5600 แบบที่ใช้จริง

ผู้สั่งงาน: Claude (แม่งาน ตรวจรับ) · ผู้ทำ: **Codex Luna** · Codex Astra: ตรวจ datasheet ข้อ 3 ถ้า Luna หาไม่ชัด
วันที่: 17 กันยายน 2026 · รันจาก `prototype-v1/`

**ลำดับ:** เริ่มหลังโค้ด LUNA-07 เสร็จ (แก้ `main.cpp` ชุดเดียวกัน ห้ามแก้ชนกัน) · LUNA-09 (เว็บ) ทำคู่ขนานได้
ใบนี้คือ **ขั้น 3 ส่วนแรกของ LUNA-08**: ให้เซนเซอร์อ่านได้จริงและวัดคุณภาพ **ยังไม่ต่อมุมเข้าการวาดทะเล** (รอเรขาคณิตใหม่จาก LUNA-09)

## 1. การใช้งานจริงที่เทสต้องเลียนแบบ

| เรื่อง | ของจริง |
|---|---|
| ลูกบาศก์ | ตั้งบนมุม หมุน**ด้วยมือ**รอบแกนตั้ง (แกนทแยงผ่านตัว) |
| บอร์ด ESP32 | **หมุนไปพร้อมจอ** บนถาดหมุนใต้ลูกบาศก์ (แก้ 17 ก.ย. ตามที่ผู้ใช้ตกลงไว้) · สายที่บิดมีแค่ USB |
| AS5600 | อยู่บนถาดหมุนกับบอร์ด **คว่ำชิปลง ตรงกลางแกน** |
| แม่เหล็ก | แบบ diametric (ขั้ว N/S อยู่คนละซีกของหน้าแม่เหล็ก) ติดนอนบน**เสากลางฐานที่นิ่ง** ห่างชิปราว 1–2 มม. |
| ระยะหมุน | **ไม่มี slip ring** หมุนได้ราว 270° หรือจนสายจอตึง |
| ขณะหมุน | จอ 6 ใบทำงานพร้อมกัน (โหลดไฟ 3V3 และ SPI จริง) |
| ลักษณะการหมุน | ค่อย ๆ หมุน, หยุดค้าง, กลับทิศ, สะบัดเร็ว, แกนอาจส่ายเล็กน้อย |

## 2. การต่อสาย (ผู้ใช้ยืนยันขาแล้ว)

| ขา AS5600 | ต่อเข้า | หมายเหตุ |
|---|---|---|
| VCC | **3V3** ของบอร์ด | **ห้ามต่อ 5V** (ถ้าโมดูลดึง SDA/SCL ขึ้นไป VCC ขา ESP32 จะโดน 5V) |
| GND | GND | ร่วมกับจอ |
| SDA | **GPIO1** | |
| SCL | **GPIO2** | |
| DIR | **GND** | ห้ามลอย ไม่งั้นทิศมั่ว |
| OUT | ไม่ต่อ | |
| GPO / PGO (ถ้ามี) | ไม่ต่อ | |

โมดูลของผู้ใช้มี 6 รู ยังไม่บัดกรี · ชื่อขาให้ยึดตามที่พิมพ์บนแผ่นจริง ถ้าไม่ตรงตารางนี้ **หยุดแล้วถามผู้ใช้**

## 3. ตรวจก่อนผู้ใช้บัดกรี/เสียบไฟ (ตอบผู้ใช้ให้เร็วที่สุด)

อ่าน datasheet ของ ams AS5600 และดูโมดูลจริง (ขอรูปสองด้านจากผู้ใช้) แล้วตอบพร้อมอ้างหน้า/หัวข้อ datasheet:
1. **ใช้ไฟ 3.3V ต้องบริดจ์ขา VDD5V กับ VDD3V3 ไหม** และโมดูลรุ่นนี้ทำไว้แล้วหรือมีจุดให้บัดกรี
2. บนโมดูลมี pull-up SDA/SCL ไหม ไปต่อกับไฟเส้นไหน
3. DIR, OUT, GPO: ยืนยันว่าต่อ/ไม่ต่อตามข้อ 2 ถูก
4. ที่อยู่ I2C, register RAW ANGLE, STATUS (MD/ML/MH), AGC, MAGNITUDE — ใช้ค่าจาก datasheet ไม่ใช่จากความจำ

## 4. งานโค้ด

**เฟิร์มแวร์**
1. โมดูลแยก `firmware/src/sensors/as5600.{h,cpp}` ใช้ `Wire` ของ framework เท่านั้น ไม่เพิ่มไลบรารี · ไม่ขึ้นกับ renderer
2. อ่านที่ ≥ 50 Hz โดย**ไม่ทำให้ลูปวาดจอช้าลง** (เช่นงานแยกบนอีกคอร์) · I2C มี timeout · นับจำนวนอ่านพลาด
3. ทำงานใน **sweep mode ของ LUNA-07** ด้วย: จอวนสีตามเดิม เซนเซอร์อ่านไปพร้อมกัน
   - เพิ่มข้อความบรรทัดเดียวบนจอ เช่น `YAW 123.4  MAG OK` ในแถบดำที่มีอยู่ ห้ามเปลี่ยนลำดับวาด ความเร็ว SPI หรือคำสั่งเปิดจอ
4. telemetry ผ่าน `sendLine` เส้นเดิมเท่านั้น (**ห้ามสองงานเขียน Serial สลับกันกลางบรรทัด**): ขณะมุมเปลี่ยน ≥ 20 บรรทัด/วินาที, นิ่ง 2 บรรทัด/วินาที
   ฟิลด์: `raw`, `deg`, `status` (md/ml/mh), `agc`, `magnitude`, `i2c_errors`, `sample_hz`
5. **ตั้งศูนย์และช่วงหมุน:** คำสั่ง serial
   - `as5600_cal_start` → ผู้ใช้หมุนสุดซ้ายสุดขวา → `as5600_cal_stop` บันทึก min/max ของช่วงที่หมุนได้จริง
   - ตั้ง offset ให้**จุดวนรอบ 359→0 ไปตกในช่วงที่หมุนไม่ถึง** (ช่วงว่าง ~90°) → มุมเป็นค่าสัมบูรณ์ รีบูตกลางทางก็ยังถูก ไม่ต้องนับรอบ
   - `as5600_zero` ตั้งมุมตอนนี้เป็น 0 · เก็บทั้งหมดลง **NVS ของ ESP32 (`Preferences`)**
6. แม่เหล็กหาย/เซนเซอร์หาย → รายงาน `ok:false` พร้อมเหตุผล คงค่าล่าสุด **ห้ามแต่งมุม**

**โน้ตบุ๊ก** — `tools/as5600_watch.py`
- ใช้ `SerialWorker` เดิม (เจ้าของพอร์ตคนเดียว DTR=1 RTS=0) · ไม่เพิ่ม dependency
- แสดงสดในเทอร์มินัล: มุม, สถานะแม่เหล็ก, AGC, อัตราอ่าน · เก็บ CSV ลง `output/as5600/`
- โหมดสรุปท้ายรอบ: jitter ตอนนิ่ง (p-p และ SD), ก้าวกระโดดใหญ่สุดระหว่างสองตัวอย่าง, ช่วงมุมที่หมุนได้, AGC/magnitude ต่ำสุด–สูงสุดตลอดช่วง, flag ML/MH ที่เคยขึ้น, i2c_errors

**เทสบนเครื่อง (ไม่ต้องมีบอร์ด):** คณิตศาสตร์ offset/จุดวนรอบ/ช่วงหมุน เป็นฟังก์ชันล้วน มีเทส Python และ native C++ ผ่าน vectors ชุดเดียวกัน (แบบเดียวกับ `cube_math`)

## 5. ขั้นเทสกับของจริง (Luna สั่ง ผู้ใช้หมุน)

| # | ทำ | ผ่านเมื่อ |
|---|---|---|
| 0 | เทส + build + แฟลช | เทสผ่าน · log มี I2C เจออุปกรณ์ที่ที่อยู่ของ AS5600 |
| 1 | **แม่เหล็กอยู่ห่าง** / ไม่มีแม่เหล็ก | รายงาน magnet ไม่พบ (พิสูจน์ว่าไม่แต่งค่า) |
| 2 | ใส่แม่เหล็ก วางนิ่ง 60 วินาที | MD=1, ML=0, MH=0 · รายงาน jitter จริง (เป้า p-p ≤ 1°) |
| 3 | หมุนช้า ๆ จนสุดทางหนึ่ง แล้วกลับสุดอีกทาง × 3 รอบ | มุมเปลี่ยนต่อเนื่อง ไม่มีกระโดด · กลับจุดเริ่มคลาด ≤ 1° · ML/MH ไม่ขึ้นตลอดช่วง |
| 4 | `as5600_cal_start` → หมุนสุดสองทาง → `cal_stop` | ได้ช่วงหมุนจริง (คาด ~270°) · จุดวนรอบอยู่นอกช่วง |
| 5 | หมุนตามเข็มนาฬิกา (มองจากด้านบน) | บันทึกว่ามุมเพิ่มหรือลด (ใช้ตั้ง `kYawReverse` ภายหลัง) |
| 6 | สะบัดเร็ว ๆ ไปกลับ 10 วินาที | ไม่มี i2c_errors เพิ่ม · ไม่มีค่ามั่วนอกช่วง |
| 7 | หยุดที่ 3 ตำแหน่ง ถอดไฟ-เสียบใหม่ทุกตำแหน่ง | มุมหลังรีบูตตรงเดิม ≤ 1° |
| 8 | ทั้งหมดนี้ขณะจอ 6 ใบวน sweep | รอบวาดจอไม่ช้าลงเกิน 10% · จอไม่ดับ |

ถ้าลูกบาศก์ยังประกอบไม่เสร็จ: ทำแท่นชั่วคราวให้ AS5600 คว่ำชิปลงอยู่บนส่วนที่หมุน และให้แม่เหล็กอยู่ในหลุมของฐานที่นิ่งตรงแกนเดียวกัน โดยคงระยะ 1–2 มม. เทสขั้น 0–7 ได้ก่อน แล้วรันซ้ำเมื่อประกอบจริง และระบุในรายงานว่าเทสบนอะไร

## 6. แยกอาการ

| อาการ | น่าจะเป็น |
|---|---|
| I2C หาไม่เจอ | SDA/SCL สลับ, ไม่มี pull-up, VCC/GND, ยังไม่บริดจ์ 3.3V (ข้อ 3.1) |
| MD=0 | แม่เหล็กไกลเกิน/ไม่ตรงศูนย์/ไม่ใช่ diametric |
| ML=1 (อ่อนไป) | ห่างเกิน |
| MH=1 (แรงไป) | ใกล้เกิน |
| มุมกระโดดเป็นช่วง ๆ ตอนหมุน | แม่เหล็กเยื้องศูนย์ หรือแกนส่าย — ดู AGC/magnitude แกว่งตามมุมไหม |
| ทิศกลับไปมา | DIR ลอย |
| ค่านิ่งแต่สั่นมาก | สายยาว/รบกวนจาก SPI — รายงานก่อน ห้ามใส่ filter หนัก ๆ กลบ |

## ห้าม

- **เขียน register BURN ของ AS5600 หรือเบิร์น ZPOS/MPOS/MANG ลง OTP** (เบิร์นแล้วแก้ไม่ได้ จำกัดจำนวนครั้ง) — เก็บค่าตั้งใน NVS ของ ESP32 เท่านั้น
- จ่ายไฟ AS5600 จาก 5V
- ขับ GPIO1/2 เป็น output
- เอามุมไปขับการวาดทะเลในใบนี้
- เปลี่ยนความเร็ว SPI/คำสั่งเปิดจอของ sweep
- เสียบ/ถอดสายขณะมีไฟ
