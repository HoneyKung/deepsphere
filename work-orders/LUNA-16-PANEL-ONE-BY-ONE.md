## ต้องทำ
1. สร้าง env `panel-one` (คัดลอกค่า platform/board/lib_deps/upload จาก env `diag`) ที่ build เฉพาะ `diag/panel_one.cpp`
2. เฟส A "ทีละใบ": วนจอ 1→6 ใบละ 8 วินาที ตอนทดสอบใบไหน ให้ init และวาดเฉพาะ CS ใบนั้น CS ใบอื่นต้องค้าง HIGH ตลอด วาดเต็มจอด้วยสีประจำใบ (6 สีไม่ซ้ำ) และตัวหนังสือใหญ่บอกเลขลำดับ ชื่อหน้า (px/nx/py/ny/pz/nz ตาม `kCs`) และเลข GPIO ของ CS ครบ 1 รอบแล้วไปเฟส B
3. เฟส B "พร้อมกัน": init ทั้ง 6 ใบแล้ววาดทุกใบพร้อมกันค้าง 20 วินาที แล้วกลับไปเฟส A วนแบบนี้ตลอด
4. พิมพ์ทาง Serial ทุกครั้งที่เปลี่ยนจอหรือเปลี่ยนเฟส เช่น `panel_one: phase=A idx=3 face=py cs=4` แต่ห้ามให้การทำงานต้องพึ่ง Serial เพราะเจ้าของจะเสียบที่ชาร์จมือถือแทน USB คอมได้
5. ถ้ามีคนพิมพ์ทาง Serial: กด `1`–`6` = ล็อกค้างที่ใบนั้น, `b` = ค้างเฟส B, `a` = กลับไปวนอัตโนมัติ
6. Build ให้ผ่าน เก็บ log ไว้ที่ `output/luna-16/build.log` จด MD5 ของ `firmware.bin` ถ้าบอร์ดเสียบอยู่ (หาพอร์ตจากรายการพอร์ต ESP32-S3) ให้แฟลช แล้วเก็บ log ที่ `output/luna-16/upload.log` ถ้าบอร์ดไม่ได้เสียบ ให้เขียนคำสั่งแฟลชที่คัดลอกไปรันได้ไว้ในรายงาน
7. เขียน `output/luna-16-status.md` ให้มี "ตารางผลวัดสำหรับเจ้าของกรอก" ตามหัวข้อส่งมอบด้านล่าง

## ห้ามทำ
- ห้ามผ่อนเกณฑ์ที่มีอยู่ ห้ามเพิ่มความเร็ว SPI
- ห้ามแก้ firmware ตัวอื่นหรือ config กลาง
- ห้ามสรุปว่าเสียเพราะอะไรถ้ายังไม่มีผลวัดของเจ้าของ
- ห้ามทำให้ภาษา/encoding เสีย

## ส่งมอบ (`output/luna-16-status.md`)
- ไฟล์ที่เปลี่ยน, ไฟล์ที่ไม่ได้เปลี่ยน, MD5 ของ `firmware.bin`, แฟลชแล้วหรือยัง
- ระบุชัดว่า "เขียนแล้ว / build แล้ว / แฟลชแล้ว / ยังไม่ได้ดูด้วยตา" — Luna มองจอจริงไม่ได้
- ตารางให้เจ้าของกรอก (6 แถว × คอลัมน์): ใบที่ / หน้า / CS / เฟส A ติดไหม / เฟส B ติดไหม / แรงดัน VCC–GND ที่ขาจอใบนั้นตอนเฟส A (V) / ตอนเฟส B (V)
- วิธีอ่านผล (เขียนไว้ล่วงหน้าเป็นกฎ ไม่ใช่ข้อสรุป):
  - ติดทีละใบได้ แต่พร้อมกันแล้วดับ หรือแรงดันตกต่ำกว่า 3.1 V → ไฟไม่พอ
  - ใบเดิมไม่ติด แม้ทดสอบทีละใบ → สาย CS หรือจอใบนั้น
  - ติดแค่ใบที่อยู่ใกล้บอร์ดที่สุด ใบที่ไกลกว่าไม่ติดเลย → สายร่วม (SCK/MOSI/DC/RST) ขาดช่วงหลังใบแรก
