## เหตุและหลักฐาน (สถาปัตยกรรมที่เจ้าของอนุมัติ 2026-10-27)
- มีสลิปริง 12 เส้นแล้ว → ลูกบาศก์หมุนได้ไม่จำกัดรอบ
- บอร์ด 2 ตัว: **บอร์ดหมุน** (ESP32-S3-Zero ตัวเดิม บนถาดใต้ลูกบาศก์) = จอ + AS5600 · **บอร์ดฐาน** (ESP32 ตัวที่ 2 ที่ฐานไม่หมุน) = ปุ่ม 3 ปุ่ม + ล้อ KY-040 + USB เข้าโน้ตบุ๊ก
- สลิปริง: 5V×3, GND×3, UART 2 เส้น (บอร์ดหมุน TX → บอร์ดฐาน RX และกลับกัน), เหลือสำรอง 4
- ล้อ = KY-040 หมุนได้ไม่สุด มีคลิก (CLK, DT, SW)
- เจ้าของเคยบ่นว่ากดครั้งเดียวความลึกกระโดด 100 ม. ไม่ลื่น (2026-10-08) → ล้อต้องป้อนเข้าระบบขยับลื่นเดิม ห้ามกระโดดตั้งค่าความลึกตรง ๆ
- รุ่นบอร์ดฐาน (เจ้าของยืนยัน 2026-10-28): **ESP32 รุ่นปกติ (ESP32-WROOM / DevKit) ไม่ใช่ S3** ใช้ PlatformIO board `esp32dev` และต่อ USB ผ่านชิปแปลง USB-UART บนบอร์ด (ปกติจะเป็น CP210x หรือ CH340) ไม่ได้ใช้ USB ของตัวชิปเอง
- เครื่องนี้ยังไม่มี `toolchain-xtensa-esp32` (มีแค่ของ S3) และ sandbox ดาวน์โหลดไม่ได้ → **ห้ามดาวน์โหลด** ถ้าตอนนั้นยังไม่มี toolchain ให้เขียนโค้ดให้ครบ แล้วรายงานว่า "ยังไม่ได้ build เพราะไม่มี toolchain" หัวงานจะ build เอง

## ต้องทำ
1. env `base-io` + `firmware/src/base_io.cpp` สำหรับบอร์ดฐาน
   - ขาที่หัวงานเสนอ (ESP32 ปกติ ใช้ได้ทั้งบอร์ด 30 และ 38 ขา): KY-040 CLK=GPIO32, DT=GPIO33, SW=GPIO25 · ปุ่ม Scan=GPIO26, Collect=GPIO27, Analyze=GPIO13 (ต่อลง GND และเปิด pull-up ในชิป) · UART2 RX=GPIO16, TX=GPIO17 ไปบอร์ดหมุน · ให้ตรวจกับเอกสาร ESP32 ว่าไม่ชนข้อห้ามต่อไปนี้: ขา strapping 0/2/5/12/15, ขา flash 6–11, ขา 34–39 ที่รับเข้าได้อย่างเดียวและไม่มี pull-up, และ GPIO1/3 ที่ใช้กับ USB-UART ถ้าขาไหนไม่เหมาะ ให้เปลี่ยนแล้วเขียนเหตุผลไว้ · ใส่ตารางขาลงใน `config/wiring-table.md` หัวข้อ "บอร์ดฐาน"
   - Serial ฝั่ง USB ใช้ `Serial` (UART0 ผ่านชิปแปลงบนบอร์ด) ที่ 115200
   - กันสั่น (debounce) ปุ่มและล้อ ล้อนับเป็นคลิก (detent) ไม่ใช่นับขอบสัญญาณ
   - ส่ง JSON ทีละบรรทัดทาง USB: `{"v":1,"type":"wheel","delta":±n}` (รวมคลิกในช่วง ≤20 ms), `{"v":1,"type":"button","name":"scan|collect|analyze|wheel","state":"down|up"}`
   - อ่านบรรทัดจาก UART (มาจากบอร์ดหมุน) แล้วส่งต่อออก USB โดยไม่แก้ข้อความ เพื่อให้ `type=yaw` เดิมไปถึง bridge เหมือนเดิม และส่ง event ปุ่ม/ล้อของตัวเองออก UART ด้วย (เตรียมไว้ให้บอร์ดหมุนใช้ในงานถัดไป)
   - ส่ง `{"v":1,"type":"hello","board":"base-io"}` ตอนเริ่ม
2. `laptop/twin_bridge.py`: รับ `wheel`, `button`, `hello` เพิ่มจาก `yaw` และส่งต่อให้หน้าเว็บผ่านช่องทางเดิมที่ส่ง yaw อยู่ บอร์ดหมุนที่เสียบ USB ตรง (live-yaw) ต้องยังใช้ได้ · ตอนนี้ `find_esp32s3_ports` หาเฉพาะ VID 303A ต้องให้หาพอร์ต CP210x (VID 10C4) และ CH340 (VID 1A86) ได้ด้วย โดยถ้าเจอบอร์ดฐานที่ส่ง `hello` มา ให้เลือกใช้บอร์ดฐานก่อน
3. `twin/twin.js`: `wheel.delta` → ป้อนเข้า `motion` เป็นแรงผลักแบบลื่น (เหมือนกดลูกศรสั้น ๆ) ค่าต่อคลิกเก็บใน `config/controls.json` เป็น `wheel_depth_per_click` ค่าเริ่มให้ลงสุด ≈ 3 รอบล้อ (KY-040 = 20 คลิก/รอบ) · `button` scan/collect/analyze → เรียกฟังก์ชันเดียวกับ Numpad 1/2/3 · ปุ่มกดของล้อ (`wheel`) ยังไม่ผูกคำสั่ง ให้แค่ log
4. ทดสอบที่ไม่ต้องใช้มือ: ทดสอบ bridge ด้วยบรรทัดจำลอง (wheel/button/yaw ปนกัน, บรรทัดเสีย) และทดสอบในเบราว์เซอร์ว่าใส่ event จำลองแล้วความลึกขยับลื่นและปุ่มทำงาน · ลูกศรและ Numpad เดิมยังใช้ได้
5. Build `base-io` ผ่าน (ถ้ามี toolchain) จด MD5 · **ห้ามแฟลช** เพราะเจ้าของยังไม่จับฮาร์ดแวร์ ให้เขียนคำสั่งแฟลชที่คัดลอกไปรันได้ไว้ในรายงาน
