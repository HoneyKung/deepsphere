# LUNA-08: เฟสนี้ — จอ 6 ใบ + หมุนด้วยแม่เหล็ก AS5600 + เชื่อมดิจิทัลทวินบนเว็บ

ผู้สั่งงาน: Claude (แม่งาน ตรวจรับ) · ผู้ทำ: **Codex Luna** (เขียนโค้ด build แฟลช เทสเอง เปิดเว็บเอง)
Codex Astra: ใช้ได้ถ้าต้องค้นข้อมูลหนัก (เช่น datasheet AS5600) · วันที่: 17 กันยายน 2026 · รันจาก `prototype-v1/`

## 1. เป้าหมายเฟสนี้ (ผู้ใช้ยืนยันแล้ว)

| ส่วน | ทำอะไร |
|---|---|
| จอ | **ST7789 ครบ 6 ใบ** แสดงฉากทะเลที่มีปลาว่าย (`nz` เปิดใช้งาน CS = GPIO7) |
| ทรง | **ลูกบาศก์ตั้งบนมุม 3 หน้าบน + 3 หน้าล่าง** — เรขาคณิตกำหนดใน `LUNA-09-TWIN-VERTEX-UP-GEOMETRY.md` |
| มุมหัน (yaw) | **ผู้ใช้หมุนลูกบาศก์ด้วยมือรอบแกนตั้ง AS5600 + แม่เหล็กอ่านมุม** · **ทะเลติดตัวลูกบาศก์ เป้าเล็งอยู่กับที่ในโลก** · ไม่มี slip ring หมุนได้ราว 270° |
| ความลึก | **ลูกศรขึ้น/ลง บนคีย์บอร์ดโน้ตบุ๊ก** (เหมือนเดิม) |
| การกระทำ | **Numpad 1 / 2 / 3** = Scan / Collect / Analyze |
| ดิจิทัลทวิน | หน้าเว็บ `twin/` **ต่อกับบอร์ดจริง** แสดงมุมหัน ความลึก และผลสแกนตามบอร์ด |

**บอร์ดหมุนไปพร้อมจอ** บนถาดหมุนใต้ลูกบาศก์ เพื่อไม่ให้สายจอบิด (แก้ 17 ก.ย. — ข้อความเดิม "บอร์ดอยู่ฐาน" ผิด) · สายที่ข้ามรอยหมุนมีแค่ USB ไปโน้ตบุ๊ก

**ไม่ทำเฟสนี้:** ล้อ KY-040, ปุ่มจริงบนบอร์ด, WiFi, ย้ายสามอย่างที่มีเฉพาะในทวินลงเฟิร์มแวร์ (ชั้นพ้นน้ำ, กริดแมพ, เมริเดียน — `docs/digital-twin.md` ข้อ 5), งานกลไก/slip ring

## 2. สิ่งที่พิสูจน์แล้วบนฮาร์ดแวร์ — เริ่มจากตรงนี้ ห้ามรื้อ

จากแชท 13 ก.ย. 2026 และคำยืนยันของผู้ใช้:
- **เฟิร์มแวร์หลัก (`esp32-s3-zero`) วาดฉากทะเลบนจอ 1 ใบ และผู้ใช้เห็นปลาว่ายแล้ว** — ไม่ต้องเขียน renderer ใหม่
- ชุดที่ทำให้ติด: SPI 4 MHz, ส่งคำสั่งเปิดจอซ้ำหลัง `init()` (SWRESET → SLPOUT → COLMOD 0x55 → NORON → DISPON), inversion เปิดทุกหน้า
- จอดำครั้งก่อนเกิดจากหน้าสัมผัส (สายจัมเปอร์ เบรดบอร์ด) ไม่ใช่โค้ด — ดู `docs/display-bringup-findings.md`
- แฟลช `upload_speed = 115200` + `--no-stub` · Serial DTR=1 RTS=0 · `laptop/core.py` `SerialWorker` ผ่าน soak 10 นาทีแล้ว (`output/claude-usb-stability-status.md`)
- ไฟจอทั้ง 6 จากขา 3V3 ของบอร์ด (ผู้ใช้เลือก) — **ยังไม่พิสูจน์ว่าพอ**

## 3. ด่านก่อนแตะฮาร์ดแวร์ — ถามผู้ใช้ ห้ามเดา

1. **AS5600 ต่อ SDA / SCL เข้า GPIO ไหน** ข้อเสนอของ Claude: **SDA = GPIO1, SCL = GPIO2** (ว่างเพราะปุ่มย้ายไปใช้ numpad แล้ว, ไม่ใช่ strapping pin; หลีกเลี่ยง GPIO3 ซึ่งเป็น strapping)
2. VCC ของ AS5600 → 3V3, GND ร่วม, **ขา DIR ต่อ GND** (ถ้าปล่อยลอย ทิศจะมั่ว) · โมดูลมีตัวต้านทาน pull-up บน SDA/SCL ไหม
3. แม่เหล็กเป็นแบบ **diametric** ติดนอนบนเสากลางฐานที่นิ่ง · AS5600 อยู่บนถาดหมุนกับบอร์ด คว่ำชิปลงตรงศูนย์ ห่างราว 1–2 มม.
4. ผู้ใช้บอก "ต่อเสร็จ พร้อมแฟลช" ก่อนแฟลชทุกครั้ง · **ห้ามเสียบ/ถอดสายขณะมีไฟ**

## 4. ขั้นงาน — ทำตามลำดับ แต่ละขั้นมีด่านตรวจ

### ขั้น 1 — จอติดครบ 6 ใบ (sweep)
ทำตาม `work-orders/LUNA-07-SIX-PANELS-LIGHT.md` ทั้งใบ (แก้ CS `nz` 17→7 ทุกไฟล์, เคลียร์ GPIO7 ที่ซ้ำ, `kPanelSweepTest = true`)
**ด่าน:** 6 ใบติด สีถูก วน 5 นาทีไม่ดับ → ไปขั้น 2

### ขั้น 2 — ฉากทะเลบน 6 ใบ

> **แก้ 17 ก.ย.:** ขั้นนี้ต้องรอ LUNA-09 (เรขาคณิตตั้งบนมุมในทวิน) ผ่านและผู้ใช้อนุมัติ แล้ว Claude จะออกใบพอร์ตลงเฟิร์มแวร์
> ข้อความ "ใบบน pz / ใบล่าง nz" ด้านล่างใช้ไม่ได้แล้ว — ท่าใหม่คือ px/py/pz บน, nx/ny/nz ล่าง
> ระหว่างรอ ทำขั้น 4 ด้วย `--simulate` ได้
- `kPanelSweepTest = false`, เปิด `nz`: `kDisplayEnabled[5] = true` และค่าคู่กันใน `config/faces.json` / ไฟล์ที่ `test_config_agreement` ผูก
- สร้าง vectors/header ใหม่ตามที่ README กำหนดเมื่อแก้ config (`make_vectors.py`, `make_live_vectors.py`, header ที่เกี่ยว) แล้วรัน native test
- ทวิน: เลิกทำเครื่องหมายว่า `nz` ไม่มีจอ
- เทส `test_only_enabled_faces_are_initialized` ที่ fail อยู่เดิม: ถ้าเกี่ยวกับโหมดจอเดี่ยวที่ค้าง ให้แก้ได้ในขั้นนี้ (เปิด nz แล้วต้องตรงความจริง) และรายงานว่าแก้อะไร
- **ความเร็ว SPI คง 4 MHz** · วัดและรายงานเวลาต่อ tick จริงจาก telemetry
  ถ้าผู้ใช้เห็นว่าภาพกระตุก ให้ **ขอผู้ใช้ก่อน** แล้วลอง 10 MHz ขั้นเดียว · ถ้าซ่า ถอยกลับ 4 MHz ทันที และรายงาน

**ด่าน:** ผู้ใช้เห็นทะเลครบ 6 ใบ ปลาว่ายข้ามรอยต่อจอได้ ไม่มีใบดำ/ซ่า 5 นาที · ใบบน (`pz`) และล่าง (`nz`) ไม่กลับหัว/สลับข้าง
(ถ้ากลับหรือหมุนผิด ให้บันทึกว่าใบไหนผิดแบบไหน แล้วแก้ `rotation`/`kFaceBasis` ตามที่วัดได้ ห้ามเดา)

### ขั้น 3 — AS5600 ขับมุมหัน

> **แก้ 17 ก.ย.:** ส่วนอ่านเซนเซอร์ ตั้งศูนย์ และเทสแบบใช้จริง ทำใน `LUNA-10-AS5600-REAL-USE-TEST.md` ก่อน
> ส่วนเอามุมไปขับการวาดทะเลทำหลังพอร์ตเรขาคณิตใหม่ (LUNA-09) ลงเฟิร์มแวร์แล้ว
- เพิ่ม `YawSource::kAs5600` ต่อจากของเดิม เขียนค่าเข้า `gYawDeg` ตัวเดียวกับที่ทางอื่นใช้ (`config/wiring-table.md` หัวข้อ "If a rotation sensor is ever added" วางทางไว้แล้ว)
- ใช้ `Wire` ที่มากับ framework อ่าน RAW ANGLE 12 บิต · **ไม่เพิ่มไลบรารีภายนอก**
- อ่าน STATUS (magnet detected / too weak / too strong) แล้วส่งใน telemetry ทุกรอบ
- **เซนเซอร์หาย หรือแม่เหล็กไม่อยู่** → คงมุมล่าสุด, telemetry บอก `yaw_ok: false` พร้อมเหตุผล · **ห้ามแกล้งหมุนเอง ห้ามเดามุม**
- ทำให้นิ่งโดยไม่หน่วง: deadband เล็ก ๆ + hysteresis ตอนเลือกหน้า (ตามที่ wiring-table ระบุ) · รายงานค่า jitter ที่วัดได้ตอนวางนิ่ง
- ตั้งศูนย์: คำสั่ง serial ตั้ง "มุมตอนนี้ = 0" และเก็บลง NVS (`Preferences`) ให้รอดรีบูต · มี `kYawReverse` สำหรับกลับทิศ
- I2C ต้องไม่ทำให้ลูปวาดจอค้าง: อ่านด้วย timeout สั้น ถ้าอ่านพลาดให้นับจำนวนใน telemetry
- ความลึกและ action ยังมาจากโน้ตบุ๊กผ่าน serial เหมือนเดิม · ถ้ามี `kYawSource` ที่ผูกกับ `kPhysicalControlsEnabled` ให้แยกออก เปิด AS5600 ได้โดยไม่เปิดปุ่ม/ล้อ

**ด่าน (ผู้ใช้หมุนด้วยมือ):**
1. หมุนตามเข็มนาฬิกา (มองจากด้านบน) → telemetry ค่ามุมเปลี่ยนทิศที่ตกลงไว้ · ถ้ากลับ ใช้ `kYawReverse`
2. หมุนครบ 1 รอบ → มุมกลับมาใกล้ค่าเดิม ไม่กระโดดตรง 359→0
3. หมุนแล้ว **ภาพทะเลหมุนไปกับตัวลูกบาศก์ เป้าเล็งอยู่ทิศเดิมในโลก** (เลื่อนข้ามจอ)
4. วางนิ่ง 1 นาที → ภาพไม่สั่น เป้าไม่กระพริบสลับหน้า

### ขั้น 4 — เชื่อมดิจิทัลทวิน (ทำคู่ขนานกับขั้น 1–3 ได้ ด้วย `BoardSimulator`)

**สถาปัตยกรรมที่กำหนด:** โปรแกรม Python ตัวเดียวบนโน้ตบุ๊ก (`laptop/twin_bridge.py`) เป็นเจ้าของพอร์ต COM
ใช้ `SerialWorker` เดิมจาก `laptop/core.py` (ไม่เขียนการเปิดพอร์ตใหม่) และ serve หน้า `twin/` ในตัว
ส่งสถานะบอร์ดไปเว็บ และรับคำสั่งจากเว็บส่งต่อให้บอร์ด **ใช้แค่ standard library** (เช่น HTTP + Server-Sent Events + POST)
เหตุผล: บทเรียน USB (DTR, เธรดเดียวเป็นเจ้าของพอร์ต, log เหตุการณ์) อยู่ในโค้ด Python ที่ผ่าน soak แล้ว · ไม่เพิ่ม dependency
ถ้า Luna พบหลักฐานว่าทางนี้ใช้ไม่ได้ ให้หยุดแล้วรายงานพร้อมเหตุผล ก่อนเปลี่ยนสถาปัตยกรรม

คำสั่งเปิดต้องเป็นบรรทัดเดียว เช่น `.venv\Scripts\python laptop\twin_bridge.py --port COMx` และ `--simulate` เมื่อไม่มีบอร์ด

ทวินในโหมดต่อบอร์ด:
- **บอร์ดเป็นผู้ตัดสินทุกอย่าง:** มุมหันจาก AS5600, ความลึกที่บอร์ดยืนยัน, ผล Scan/Collect/Analyze จากบอร์ด
- ถ้าผลที่ทวินคำนวณเองไม่ตรงกับบอร์ด → ใช้ผลบอร์ด และ log mismatch (นี่คือการพิสูจน์ว่าทวินเป็นทวินจริง)
- **ปิดทางหมุนอื่นทั้งหมดในโหมดนี้:** ลูกศรซ้าย/ขวา และการลากเมาส์หมุนกล่อง (ลากหมุนกล้องได้ ถ้าแยกจากมุมกล่อง) — ห้ามมีสองแหล่ง yaw แย่งกัน
- ลูกศรขึ้น/ลง → ส่งคำสั่งความลึกให้บอร์ด แสดงค่าตามที่บอร์ดตอบ
- **Numpad:** จับด้วย `event.code` = `Numpad1/2/3` ซึ่งไม่ขึ้นกับ NumLock
  ⚠️ ตอน NumLock ปิด Numpad2/8 จะส่ง `key` = ArrowDown/ArrowUp — ต้องเช็ค `code` ขึ้นต้นด้วย `Numpad` **ก่อน** ไม่งั้นกด Collect แล้วความลึกเลื่อน
  ตัวเลขแถวบน `Digit1/2/3` ทำงานเหมือนเดิมได้
- มุมหันบนเว็บต้องลื่น: บอร์ดส่ง yaw ถี่พอขณะหมุน (เป้า ≥ 20 ครั้ง/วินาที ขณะมุมเปลี่ยน) แล้วเว็บ interpolate · บรรทัด telemetry สั้น ไม่ให้ซ้ำปัญหาไบต์หาย
- ป้ายหัวเว็บบอกสถานะจริงเสมอ: `SIMULATED — NO BOARD` / `LIVE BOARD · COMx` / `BOARD DISCONNECTED`
  **ลิงก์หลุดห้ามกลับไปจำลองเงียบ ๆ** ด้วยมุมค้าง
- เสียงเล่นจากทวินที่เดียว · ห้ามเปิด `laptop/app.py` พร้อมกัน (พอร์ตเปิดได้ทีละโปรแกรม) — เขียนไว้ใน README

สัญญาสื่อสาร: ฟิลด์/คำสั่งใหม่ทั้งหมด (yaw source, magnet status, yaw zero, depth command, action) **เขียนลง `docs/audio-protocol.md`** และให้ Python, JS, เฟิร์มแวร์ใช้ชื่อเดียวกัน · ของเดิม (`ACK`, `session`, `EventDeduper`) ห้ามทำพัง

**ด่าน:**
1. `--simulate`: เว็บเปิด ลูกศรขึ้น/ลง, Numpad 1/2/3 (ทั้ง NumLock เปิดและปิด) ทำงานถูก · Luna เปิดเว็บทดสอบเอง
2. ต่อบอร์ดจริง: หมุนลูกบาศก์ → กล่องในเว็บหมุนทิศเดียวกัน มุมต่างไม่เกินราว 5° หลังหยุดหมุน
3. กดลูกศร → ความลึกเปลี่ยนทั้งจอจริงและเว็บ · Numpad → Scan/Collect/Analyze ผลตรงกันทั้งสองฝั่ง
4. ถอด USB → เว็บขึ้น `BOARD DISCONNECTED` · เสียบกลับ → กลับมาเองโดยไม่ต้องรีโหลดเว็บ

### ขั้น 5 — เดโมรวม 10 นาที
หมุน + ดำลึก + สแกน/เก็บ/วิเคราะห์ ต่อเนื่อง 10 นาที: ไม่รีบูต (session/uptime ต่อเนื่อง), ไม่มีจอดับ, เว็บไม่หลุด, ไม่มี mismatch ที่อธิบายไม่ได้

## 5. แยกอาการที่รู้ล่วงหน้า

| อาการ | น่าจะเป็น | ทำต่อ |
|---|---|---|
| จอดำ/backlight ติดแต่ไม่มีภาพ | หน้าสัมผัสสาย | ให้ผู้ใช้เช็คสาย **ไม่แก้โค้ด** |
| ใบเก่าดับตอนเพิ่มใบ / รีบูต | ไฟ 3V3 ตก | ย้าย USB บอร์ดไปหัวชาร์จผนัง / วัดแรงดันที่จอไกลสุด |
| มุมกระโดดมั่ว | DIR ลอย, แม่เหล็กไม่ตรงศูนย์, ระยะผิด | ดู STATUS แม่เหล็กใน telemetry ก่อน |
| AS5600 อ่านไม่ได้ | SDA/SCL สลับ, ไม่มี pull-up, ขาไม่ตรง | I2C scan หาที่อยู่ 0x36 แล้วรายงาน |
| กด Numpad2 แล้วความลึกลด | จับ `key` แทน `code` | ดูข้อ 4 ขั้น 4 |
| เว็บหมุนสวนทางกับของจริง | ทิศไม่ตรง | `kYawReverse` ที่ฝั่งบอร์ดที่เดียว ห้ามกลับทิศซ้ำในเว็บ |

หยุดส่งงานให้ Claude ตรวจ **หลังขั้น 2** และ **หลังขั้น 4** (จะได้ไม่ไปไกลบนฐานที่ผิด)

## ห้าม

- แฟลชก่อนผ่านด่านข้อ 3 หรือก่อนผู้ใช้บอกพร้อม
- รื้อ renderer ทะเล, ลบคำสั่งเปิดจอซ้ำ, ปิด inversion, เปลี่ยนความเร็ว SPI โดยไม่ขอผู้ใช้
- เพิ่มไลบรารีภายนอก (ทั้ง PlatformIO และ pip) โดยไม่รายงานเหตุผลก่อน
- มี yaw สองแหล่งพร้อมกัน, แกล้งจำลองมุมเมื่อเซนเซอร์หาย, ตัดป้ายสถานะบนเว็บ
- จ่ายไฟสองแหล่งพร้อมกัน หรือเสียบ/ถอดสายขณะมีไฟ
