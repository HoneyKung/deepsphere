## 2. นำไฟล์เข้าโปรเจกต์ + ตรวจไฟล์

1. ย้ายของเดิม `ambient_surface/mid/deep.wav` ไป `assets/audio/legacy/` (ไม่ลบ เผื่อย้อน)
2. ก๊อปปี้ 13 ไฟล์ใหม่เข้า `assets/audio/` ใช้ชื่อตัวพิมพ์เล็กตาม cue id (`ambient_surface.wav`, `hull_creak_1.wav` …) ห้ามเปลี่ยนไฟล์ต้นฉบับใน G:
3. ตรวจแต่ละไฟล์ด้วย Python (มี Python 3.14, ไม่มี ffmpeg; ใช้ `wave` + `numpy` ถ้ามี) เขียนผลลง `output/luna-12-audio-inspect.md`: ความยาว, sample rate, channel, bit depth, peak/RMS dBFS, ช่วงเงียบหัวท้าย, **แยกจุดเสียงดังในไฟล์ยาว** (hull_creak ×6, whale, sonar_idle) ว่าแต่ละไฟล์มีกี่เหตุการณ์ ช่วงเวลาที่
4. ไฟล์ยาวที่มีหลายเหตุการณ์ → **ตัดเป็นไฟล์ย่อยหรือทำ index ตำแหน่งเริ่ม–จบ** (เก็บใน `assets/audio/cuts.json`) แล้วให้ตัวเล่นสุ่มเลือกเหตุการณ์เดียวต่อครั้ง ผลคือ creak 1–3 วิ สุ่มจาก 6 ไฟล์ × หลายจุด, วาฬ 4–10 วิ, ปิงโซนาร์ 1 ปิงต่อครั้ง
5. ไฟล์ loop ตรวจรอยต่อ ถ้าสะดุดให้ครอสเฟดหัวท้าย 1–2 วิตอนเล่น (ไม่แก้ไฟล์ต้นฉบับ) · ปรับระดับเสียงให้ใกล้กัน (ตั้ง `gain` ต่อ cue ใน `catalog.json`) อย่า normalize ทำลายไฟล์ · ตั้งเป้า roomtone ≈ −24 dBFS RMS, ambient ≈ −24, creak/ping สูงสุดไม่เกิน −3 dBFS peak หลังคูณ gain
6. ขนาดรวมประมาณ 100 MB: ถ้าเปิดหน้าช้า ให้แปลง `.ogg`/`.mp3` เฉพาะสำเนาที่เว็บใช้ได้ แต่ต้องเก็บ WAV ไว้ และบอกในรายงาน

## 3. เปลี่ยนระบบเสียงของทวินเป็น WebAudio

`twin.js` ตอนนี้ใช้ `new Audio()` เล่น 8 cue เท่านั้น ต้องเปลี่ยนเป็น:

- `AudioContext` เดียว + decode ไฟล์เป็น buffer (โหลดตอนกดเริ่ม แสดง "กำลังโหลดเสียง n/N" บนปุ่มเริ่ม ห้ามค้างหน้าจอ)
- ลูปไร้รอยต่อด้วย `AudioBufferSourceNode.loop` (ambient 3 โซน, roomtone)
- **5 บัส**: `bed` (ทะเล) · `hull` (ตัวเรือ) · `life` (สิ่งมีชีวิต) · `tool` (เครื่องมือ) · `voice` (พากย์) → master gain → ปลายทาง ปุ่ม M ปิดทั้งหมด (รวมเสียงพากย์ที่กำลังพูด) · มีแถบ volume
- `duck()` ตอนพากย์พูด: bed ×0.45, life ×0.6, hull ×0.7 (ค่าจากอาร์ติแฟคต์)
- ครอสเฟดโซน 0.6 วิ (ของเดิมมีใน `fade()` ย้ายมาใช้บัสใหม่), เมื่อ `state.zone` เปลี่ยน
- แพนซ้ายขวา (StereoPanner) สำหรับเสียงสิ่งมีชีวิต ตามทิศ
- ย้ายโค้ดจาก `soundmap-reference.html` ได้เลย ฟังก์ชัน `out(bus,gain,pan,rev)` และรีเวิร์บอย่างง่าย
- รหัส cue ทุกตัวต้องตรงกับ id ในอาร์ติแฟคต์ และ `docs/audio-protocol.md` กับ `assets/audio/catalog.json` ต้องอัปเดตให้มี id ใหม่ทั้งหมด (พร้อมช่อง `source`: `file` / `draft` / `none`)

## 5. cue ที่ยังไม่มีไฟล์ ให้เสียง "ร่าง" แทน เพื่อให้เสียงเต็มวันนี้

อาร์ติแฟคต์มีโหมด "เต็มตัวตามแผน" ที่สร้างเสียงร่างสังเคราะห์ด้วย WebAudio (ปิงโซนาร์ เสียงคลิกหมุน บูมข้ามโซน ฯลฯ) → **ย้ายตัวสร้างนั้นมาเป็น fallback** ทุก cue ที่ `source` เป็น `none` ไม่มีไฟล์ในโฟลเดอร์ ให้ใช้เสียงร่างนี้ ถ้าวันหลังมีไฟล์จริงก็แค่วางไฟล์ตามชื่อ cue id (`assets/audio/<id>.wav` หรือ `<id>_1..n.wav` สุ่มสลับ) แล้วระบบเลือกไฟล์แทนเสียงร่างเอง ไม่ต้องแก้โค้ด

**เสียงพากย์:** ใช้ `speechSynthesis` ของเบราว์เซอร์เป็นเสียงร่าง (ไม่มีไฟล์พากย์ และอย่าไปเอาแคช gTTS เก่า ซึ่งบทเก่าไม่ตรงกับทวินนี้)
- ตัวเลือกภาษา ไทย / English / ปิด ค่าเริ่มต้น **ไทย** (ผู้ฟังเป็นเพื่อนร่วมชั้นคนไทย) ถ้าเครื่องไม่มีเสียงไทยให้สลับเป็นอังกฤษอัตโนมัติและบอกในแผงตรวจเสียง
- ถ้ามีไฟล์ `assets/audio/voice/<id>_th.wav` / `_en.wav` ให้ใช้ไฟล์แทน TTS (เตรียมไว้สำหรับตอนอัดเสียงจริง)
- ตรวจว่า Chrome/Edge บนเครื่องนี้พูดไทยได้จริง ถ้าไม่ได้ บอกผม พร้อมทางเลือก

- ไม่มี error ใน console, ไม่มีเสียงตัดคลิกตอนครอสเฟด, ไม่ดังแตกตอนหลาย cue พร้อมกัน (เช็ค peak รวมด้วย `AnalyserNode` สั้น ๆ ที่ตำแหน่งลึกสุด + กดหมุน + พากย์พร้อมกัน ต้องไม่เกิน −1 dBFS)
- โหมด `?live=1` ที่ไม่มีบอร์ด: ต้องไม่พัง (board_link ลง log ได้)
- เทสที่มีอยู่ต้องผ่านเท่าเดิม (fail เดิมคือ `test_only_enabled_faces_are_initialized` ห้ามไปแตะ) เพิ่มเทสเล็ก ๆ ว่า id ใน `catalog.json` ตรงกับ cue ที่โค้ดเรียกทุกตัว และไฟล์ที่ catalog อ้างมีอยู่จริง
- สรุปท้ายรายงาน: จำนวน cue ที่เล่นจากไฟล์จริง / จากเสียงร่าง / เงียบ, ปัญหาที่เจอในไฟล์ของเพื่อน (เช่น ไฟล์ยาวผิดปกติ รอยต่อลูป เสียงแตก) ให้ผมส่งต่อเพื่อน
