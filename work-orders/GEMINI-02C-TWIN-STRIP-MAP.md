ตรงกับที่ผู้ใช้สั่งตั้งแต่แรก: **คลี่เป็นข้าวหลามตัดบน 3 ต่อกับล่าง 3**

## 1. การแมพใหม่: แผ่นทะเลแบน = แถบคลี่ 6 หน้า

แถบ (strip) คือมุมมองคลี่ที่มีอยู่แล้วในทวิน (เทส "rhombic unfold shared upper/lower edges coincide" ผ่านแล้ว) — ใช้แถบนี้เป็น**พิกัดของภาพทะเลโดยตรง**

- ลำดับรอบตัว (azimuth เพิ่ม): **px(บน) → nz(ล่าง) → py(บน) → nx(ล่าง) → pz(บน) → ny(ล่าง)**
- แต่ละหน้าในแถบ = ข้าวหลามตัด เส้นทแยง **D = 50√2 ≈ 70.711 มม.** · คลี่แบบรักษาระยะจริง (isometric) → **ระยะในแถบ = ระยะจริงบนกระจก ไม่มียืด**
- พิกัดแถบ `(x, y)` หน่วย มม.:
  - `y = h · √(3/2)` (ระยะตามแนวลาดลงของหน้า) · จุดกลางหน้าบน `y = +17.678` · จุดกลางหน้าล่าง `y = −17.678`
  - จุดกลางหน้าบนอยู่ที่ `x = 0, 70.711, 141.421` · หน้าล่างอยู่ที่ `x = 35.355, 106.066, 176.777`
  - `x` วนรอบที่ **212.132 มม.** (= 3D)
- ทุกพิกเซลของทุกจอ → จุดบนหน้า (มม.) → `(x, y)` ในแถบ ด้วย affine ต่อหน้า (หมุน + เลื่อน ไม่ต้องใช้ `atan2`/`asin`)

**ผลที่ต้องได้**
- **ขอบบน↔ล่าง 6 เส้น:** ภาพต่อกันเนียนทุกอย่าง (เป็นขอบที่ติดกันในแถบ)
- **ขอบบน↔บน 3 เส้นรอบมุมบน และล่าง↔ล่าง 3 เส้นรอบมุมล่าง:** ในแถบมีช่องว่างสามเหลี่ยมคั่น
  - จุดที่**ความสูงเท่ากัน**บนสองฝั่งคือจุดเดียวกันบนขอบจริง → เส้นแนวนอนและปลาที่ว่ายแนวนอน**ข้ามแล้วโผล่ตำแหน่งถูก**
  - ภาพที่ไม่สมมาตร เช่นลายหิน ตรงรอยนี้อาจไม่ต่อกันพอดี ยอมรับได้ เพราะอยู่ใต้กรอบ 10 มม. ทั้งหมด → บันทึกในรายงาน
- **ขอบทั้ง 12 เส้นอยู่ใต้กรอบ** ไม่มีรอยต่อไหนอยู่บนกระจก

## 2. เส้นกริด
- ช่องสี่เหลี่ยมจัตุรัสเท่ากันในแถบ ระยะห่าง `D / 6 ≈ 11.785 มม.` ทั้งแนวนอนและแนวตั้ง (มุมของทุกหน้าตกบนเส้นกริดพอดี → เส้นแนวตั้งมาพบกันที่รอยบน↔บนแบบสมมาตร)
- บนจอจริงจะเห็นช่องเท่ากันหมด เส้นตรง **เอียงตามแนวทแยงของจอ** (เพราะจอเป็นข้าวหลามตัดเมื่อมองจากข้าง) — ถูกต้อง

## 3. ความลึก
- เลื่อนแผ่นทะเลในแนว `y`: `y_sea = y_strip + scroll(depth)` (หรือเครื่องหมายที่ทำให้**ดำลึกแล้วภาพและปลาเลื่อนขึ้น**)
- พื้นหลัง เส้นกริดแนวนอน และปลา เลื่อนด้วยค่าเดียวกัน · เส้นกริดแนวตั้งไม่เปลี่ยนตามความลึก
- ปลาชนิดที่ลึกกว่าโผล่จากด้านล่าง · ทิศปุ่มลูกศรคงเดิม

## 4. ปลา
- ตำแหน่ง `(x, y_sea)` มม. · ขนาด `w_mm`, `h_mm` · ว่ายตาม `x` ที่ `y` คงที่ ความเร็ว มม./วินาที (closed-form จากเวลา ห้ามสะสมทีละเฟรม)
- ตัดสินพิกเซลในปลาด้วย `Δx, Δy` ในแถบโดยตรง → ไม่ยืดโดยอัตโนมัติ
- ผ่านช่องว่างสามเหลี่ยม (ข้อ 1): ล่องหนระหว่างทาง แล้วโผล่ที่ความสูงเดิมบนหน้าถัดไป — **ตำแหน่งต้องถูก** · เวลาที่หายเพิ่มจากช่องว่าง บันทึกไว้ในรายงาน
- hit test = สีพิกเซล ฟังก์ชันเดียวกัน

## 5. เป้าเล็ง
- อยู่ที่ **`y = +17.678`** (เส้นผ่านกลางจอบนทั้งสาม) · `x = x_px_center + yaw/360 × 212.132` (เชิงเส้น ความเร็วเท่ากันบนจอ)
- ต่างจาก azimuth จริงไม่เกินราว 6.5 มม. ระหว่างกลางหน้ากับมุม — ยอมรับได้ เพราะเป้าเป็นสิ่งที่วาดขึ้น ไม่ใช่ของจริง · รายงานค่าที่คำนวณได้
- ที่ yaw 0° / 120° / 240° เป้าอยู่กลางจอ px / py / pz พอดี · ข้ามหน้าที่มุมข้าง (ใต้กรอบ)
- % เวลาที่เป้าอยู่บนจอ คำนวณด้วยนิยามนี้ใหม่ แล้วรายงาน

## 6. เทส (Python + Node ผ่าน vectors ชุดเดียว)
1. isometric: ระยะระหว่างพิกเซลสองจุดบนหน้าเดียวกัน = ระยะในแถบ (≤ 0.05 มม.)
2. ขอบบน↔ล่าง 6 เส้น: จุดเดียวกันบนขอบจากสองหน้า ได้ `(x, y)` เดียวกัน (≤ 0.05 มม.)
3. ขอบบน↔บน/ล่าง↔ล่าง 6 เส้น: จุดเดียวกันบนขอบได้ `y` เดียวกัน (≤ 0.05 มม.)
4. กริด: ทุกช่องบนทุกจอเป็นสี่เหลี่ยมจัตุรัสด้านเท่า (≤ 1 px) · เส้นตรง (≤ 1 px)
5. ความลึก: เปลี่ยนความลึก → ปลาและพื้นหลังเลื่อน `Δy` เท่ากัน
6. เป้าเล็ง: ข้อ 5 · ปลา: สัดส่วนวงกลมทดสอบ 1.00 ± 0.02 ทุกตำแหน่ง
7. hit test = สีพิกเซล (ของเดิมยังผ่าน)

ลบหรือปรับเทส `(φ, h)` เดิมที่ขัดกับนิยามใหม่ — อย่าลบเงียบ ๆ ระบุในรายงานว่าเปลี่ยนอะไร
