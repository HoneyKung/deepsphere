# ใบสั่งงาน: 5.6 Luna — โค้ดต้นแบบใหม่

สถานะ: พร้อมส่งให้ผู้เขียนโค้ด ยังไม่ได้ dispatch

## คำสั่งงานพร้อมใช้

ทำงานใน `C:/Users/Acer/Downloads/oceanX/prototype-v1` สร้างโค้ดใหม่สำหรับ ESP32-S3-Zero และจอ ST7789 240×240 หกใบ รวมเครื่องมือแปลงภาพชั้นทะเลและแผงควบคุมเรือดำน้ำบนโน้ตบุ๊กที่แสดงภาพเก็บ ข้อมูลวิเคราะห์ และเล่นเสียง อ่าน `README.md`, `docs/system-plan.md`, `docs/audio-protocol.md` และ `docs/delivery-plan.md` ก่อนเริ่ม

ห้ามอ่าน นำเข้า คัดลอก หรืออ้างใช้โค้ด ภาพ เสียง และ dependency จาก `../demo/` หรือเดโมเก่า เริ่มไฟล์ source และ asset ใหม่ ไม่ต้องสำรวจเอกสารโครงการอื่นเพื่อเปลี่ยนข้อกำหนด ผู้ใช้ปั้น 3D และประกอบฮาร์ดแวร์เอง อย่าแก้ CAD หรือรายการซื้อโดยพลการ ห้ามใส่อีโมจิในไฟล์โค้ด

เป้าหมายคือภาพชั้นทะเลแบบคลี่แมพลงหกหน้า ภาพปลา/ทะเลคงพิกัดบนตัวลูกเมื่อหมุน เฉพาะเป้าเล็งเคลื่อนชดเชยมุมเพื่อคงทิศหน้าฐาน ล้อเลื่อนระดับทะเล ปุ่มยืนยันแล้วคือ Scan/Collect/Analyze จอคอมเป็นแผงควบคุมเรือดำน้ำ แสดงภาพที่เก็บและรายละเอียด พร้อมเล่นเสียงโดยรับเหตุการณ์ USB Serial

## งานเรียงลำดับ

### L1 — Scaffold ที่ build ได้และ driver จอ

- สร้างโครงการ C++ Arduino-ESP32 พร้อม build config ที่ตรง Waveshare S3-Zero รุ่นจริง ล็อกเวอร์ชันหลัง build ผ่าน
- แยก pin map และ face config ออกจาก renderer ขาที่ผู้ใช้ยังไม่ยืนยันต้องมีสถานะ ไม่ปล่อยให้ hardware mode ขับขาเดา
- ตรวจ PSRAM runtime และรายงานเมื่อไม่มี ไม่ปล่อยให้ allocation ล้มแล้ววาดต่อ
- ใช้ hardware SPI บัสเดียว CS แยกหกจอ เริ่มจาก pattern หนึ่งจอแล้วหกจอ และตั้ง bus speed ผ่าน config
- ส่ง wiring table หมายเลข GPIO จริง ชื่อขาบอร์ด ชื่อขาจอ และส่วนที่แชร์ให้ผู้ใช้ยืนยันก่อนต่อครบ ห้ามใช้ตารางนับ GPIO เดิมแทนผังจริง
- USB CDC ต้องไม่ทำให้โปรแกรมรอเชื่อมคอมตลอดไป และคงทางแฟลช/ดีบั๊กได้

### L2 — Atlas ใหม่และเครื่องมือแมพ

- สร้างภาพชั้นทะเลใหม่แบบเรียบง่าย 1024×512 พร้อม grid/debug mode เพื่อเริ่มระบบ ห้ามหยิบภาพเก่ามาแก้สี
- สร้างเครื่องมือแปลง PNG เป็น RGB565 พร้อม metadata และตรวจขนาดจริง/byte order ส่ง asset pack ชุดเดียวกันให้บอร์ดกับแผงคอม พร้อม pack id ที่ตรวจความตรงกันได้และภาพที่ quantize ตรงกัน
- แยก sea atlas, targets metadata และค่าระดับความลึกออกจาก code; ใช้ target_id จำลองก่อน ไม่ตั้งชื่อวิทยาศาสตร์หรือข้อมูลความลึกโดยไม่มีแหล่ง
- ทำ preview ใหม่ที่แสดงหกหน้าแยกกันและปรับ yaw/depth ได้ ใช้เครื่องมือเรียบง่าย เช่น Python/Pillow สำหรับภาพและชุดเฟรมตรวจ ไม่ต้องสร้างเว็บสามมิติเต็มตัว
- ใช้โมดูลคณิตศาสตร์ที่ตรวจได้ และป้องกันสูตรใน preview กับ firmware ไม่ตรงกันด้วย test vectors เดียวกัน
- พื้นหลังรับ depth แต่ไม่รับ yaw ในขั้นเลือกภาพ; reticle รับ yaw ตามสูตรในแผน

### L3 — อินพุต เป้าเล็ง และการสแกน

- เพิ่ม AS5600, KY-040 และปุ่ม มี debounce, ตั้งศูนย์, ทิศกลับเซนเซอร์ และการข้าม 359→0
- มี fake-input mode สำหรับพัฒนา ไม่ปลอมสถานะว่าอ่านเซนเซอร์จริง
- คำนวณจุดเป้าบน active image จาก ray/cube intersection ไม่แค่เลือกจอแล้ววาดกึ่งกลาง
- ลบเป้าเก่าอย่างถูกต้อง ซ่อนช่วงกรอบ และใช้ displayed scene state สำหรับ hit test ขณะเปลี่ยนความลึก
- ทำ target hit/miss จาก UV metadata รวม seam แนวนอน และ rate limit การกด
- Collect ตรวจเป้าปัจจุบันและส่ง snapshot ของ crop/target/depth/sample_id ตาม protocol รอ ACK แบบไม่บล็อกก่อนแสดงว่าเก็บบนคอมสำเร็จ ไม่บังคับ Scan ก่อน Collect โดยไม่มีคำสั่งเพิ่ม
- Analyze ส่งเหตุการณ์ให้คอมเลือกตัวอย่างในคลังตามกติกา ไม่เปลี่ยนความลึกหรือรีเซ็ตฉาก

### L4 — แผงควบคุมเรือดำน้ำ ภาพที่เก็บ และเสียง

- สร้างแผง Python/Tkinter/Pillow พร้อม serial reader และ audio mixer ในโปรแกรมเดียว ตาม `docs/audio-protocol.md` อ่าน catalog ที่ Claude จะส่ง ไม่ต้องรอไฟล์เสียงครบเพื่อเขียนแผง
- แผงมีสถานะความลึก/การเชื่อมต่อ ผล Scan ภาพตัวอย่างหลัก คลัง thumbnail และส่วน Analyze ไม่ใส่มาตรวัดปลอม และไม่จำเป็นต้องมี live view ของจอหกใบ
- เมื่อ Collect มา ตรวจ asset_pack ตัดภาพตาม crop จาก atlas เดียวกับบอร์ด บันทึก PNG+metadata ใน `output/samples/` แล้วเพิ่มภาพในคลังและส่ง ACK บันทึกสำเร็จ ไม่คำนวณรูปเก่าตาม depth ปัจจุบัน
- เปิดแผงใหม่ต้องโหลดคลังได้ event ซ้ำไม่สร้างภาพซ้ำ และ asset mismatch ต้องแสดงข้อผิดพลาดแทนภาพผิด
- Analyze เปิดรายละเอียดของตัวอย่างที่เลือกหรือชิ้นล่าสุด ไม่มีตัวอย่างให้แจ้งเก็บก่อน ไม่สร้าง LLM/TTS หรือข้อมูลวิทยาศาสตร์สมมติ
- มีเลือก COM, reconnect/get_state, duplicate-event protection, log ที่อ่านรู้เรื่อง และเล่น cue หรือจำลอง Scan/Collect/Analyze โดยไม่ต่อบอร์ดได้ โหมดจำลองต้องติดป้ายชัดเจน
- เล่น loop ambience และ one-shot พร้อมกันได้ เปลี่ยนโซนแบบ crossfade ไม่ restart ทุก state
- ไฟล์เสียงขาด/พอร์ตหลุดต้องไม่ crash หรือทำเฟิร์มแวร์ค้าง อย่าดึงเสียงเก่ามา fallback
- จัดการการแย่ง COM ระหว่างแฟลช serial monitor และ receiver ในคู่มือ
- ไม่เริ่มเขียน Wi-Fi transport จนผู้ใช้ยืนยันว่าต้องใช้เพราะทางไฟ/USB มีปัญหา

## สิ่งที่ต้องส่ง

1. โค้ด build ได้ พร้อมเวอร์ชัน dependency และคำสั่งที่ใช้จริง
2. `config/` ที่มี pin map, หน้าจอ, active image, zero offset และ controls ไม่กระจายค่าตั้งทั่ว source
3. ภาพใหม่/เครื่องมือแปลงพร้อมไฟล์ตัวอย่างที่สร้างจริง
4. แผงควบคุมโน้ตบุ๊กที่ทดสอบด้วย event จำลองได้ เก็บ/เปิดภาพตัวอย่างได้ และ requirements ที่ติดตั้งซ้ำได้
5. คู่มือสั้นจาก clean setup ไปถึง build, flash, จอหนึ่งใบ, หกใบ และเสียง
6. บันทึกใน `output/implementation-status.md` ว่าอะไรผ่านด้วยเครื่องมือ อะไรผ่านบนบอร์ด และอะไรยังรอผู้ใช้

## การตรวจที่ต้องมี

- `yaw=0` กับ `yaw=360` ได้ตำแหน่งเป้าเท่ากัน; ใกล้ 359→0 ไม่กระโดดผิดหน้า
- เปลี่ยน yaw โดย depth เดิมแล้ว hash/ข้อมูลพื้นหลังไม่เปลี่ยน
- จุดที่อยู่กรอบไม่ถูกนับว่า hit และไม่วาดออกนอกจอ
- U วนขอบภาพได้ V clamp ได้ ขนาดบัฟเฟอร์ไม่ล้นและ RGB565 ไม่สลับ byte/color
- เคส target ข้าม seam, เป้าหมายว่าง และ depth ที่กำลังเปลี่ยน ใช้สถานะเดียวกับที่แสดง
- โปรแกรมเสียงรับ state ซ้ำโดยไม่เริ่ม loop ใหม่ รับ event ซ้ำไม่เล่นซ้ำ และเริ่มรับหลังบูตได้
- Collect แล้วเปลี่ยน depth/yaw ภาพที่เก็บต้องคงเดิม เปิดแผงใหม่ยังเห็นภาพเดิม asset mismatch ไม่บันทึกรูปผิด และ event ซ้ำไม่เพิ่ม sample ซ้ำ
- Analyze ใช้ตัวอย่างที่เลือกในคลังจริง และกรณีไม่มีตัวอย่างไม่ crash
- อย่างน้อยมีผล build จริง; หากไม่มีบอร์ดเชื่อมต่อให้บอกว่ายังไม่ทดสอบ hardware ไม่เขียนว่าเดโมผ่าน

เริ่ม L1 และส่วนคณิตศาสตร์ของ L2 ได้ทันที หากมีข้อกำกวมที่ไม่ขวางงานให้บันทึกสมมติฐานและเดินต่อ หยุดเฉพาะการต่อ/ขับฮาร์ดแวร์ที่ยังไม่มีผังยืนยัน ส่งปัญหาเฉพาะจุดให้ Astra ตัดสินใจ ไม่เปลี่ยน architecture เอง
