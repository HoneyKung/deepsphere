# LUNA-14: เลขความลึกสวนทางกับภาพในเว็บทวิน (ลึก 3040 ม. แต่ภาพเหมือนผิวน้ำ)

ผู้สั่งงาน: Claude · ผู้ทำ: **Codex Luna หรือ Gemini** · วันที่: 2 ต.ค. 2026 · รันจาก `prototype-v1/`
ผู้ใช้แคปภาพ: เลข HUD แสดง **3040 METERS / DEEP / 305 ATM / 4.0°C / VISIBILITY NONE** แต่จอ 3 ใบบนของลูกบาศก์ **สว่างฟ้าอ่อนมีแถบขาวเหมือนผิวน้ำ** เลขกับภาพสวนทางกัน
ทำต่อจาก LUNA-13 (ข้อ A และ B.1–B.3 เสร็จก่อน เพราะแก้ HUD ไฟล์ละส่วน: ใบนี้แตะ `geometry.js`/`renderer.js`/`config/twin.json` เป็นหลัก)

## 1. หลักฐานที่ Claude วัดแล้ว (ในเว็บทวินจริง ค่าเฉลี่ย RGB ของจอบน px+py+pz ที่ yaw 0)

| ความลึก | ม. | RGB เฉลี่ยของภาพ | จุดที่สุ่มในแผนที่ทะเล `v` |
|---|---|---|---|
| 0 | 0 | 24,108,148 | 0.450 |
| 0.1 | 304 | 26,112,150 | 0.417 |
| 0.25 | 760 | 27,118,156 | 0.367 |
| 0.5 | 1,520 | 26,127,166 | 0.283 |
| 0.75 | 2,280 | 28,137,175 | 0.200 |
| **1.0** | **3,040** | **78,171,204** | **0.117** |

**ยิ่งลึกยิ่งสว่าง** (ควรตรงข้าม) และที่ 3,040 ม. ภาพเข้าใกล้แถบฟ้าผิวน้ำ (`v < 0.105`)

## 2. ต้นเหตุที่น่าจะเป็น (Luna ยืนยันก่อนแก้)

- `twin/geometry.js` บรรทัด ~14: `stripScrollMm = depth => (clamp01(depth) − 0.1) × step × 2` → เลื่อนพิกัดทะเลไปทาง **y เพิ่มขึ้น** เมื่อลึกขึ้น
- `twin/renderer.js` `backgroundColor()` : `v = 0.5 − stripY/length`, `deep = clamp01(v)` และแถบท้องฟ้า (`v < 0.105`) → **y ที่เพิ่มขึ้น = v ลดลง = สว่างขึ้นและเข้าใกล้ผิวน้ำ** ทิศขัดกัน
- ช่วงเลื่อนทั้งหมด (0→1) มีแค่ ~70 มม. จากความยาวแถบทะเล 212 มม. → ต่อให้ทิศถูก สีก็เปลี่ยนไม่เกินราวหนึ่งในสามของสเกล ภาพเลยไม่มืดลงพอ (ตัวเลขข้างบนแม้ที่ 0 ม. ก็ไม่ได้สว่างเหมือนผิวน้ำเต็ม ๆ)
- ปลาถูกวางโดยใช้ `scroll` ชุดเดียวกัน (`subjectAt`: `dy = y − (subjectY − scroll)`) → **เมื่อแก้ทิศ/สเกล ปลาต้องไม่หลุดความลึกที่ออกแบบไว้**

## 3. พฤติกรรมที่ต้องการ (หลักการ ให้ Luna เลือกสูตรเอง แล้วเขียนเหตุผล)

1. **ความลึกเพิ่ม → ภาพมืดลงเสมอ (monotonic)** ความสว่างเฉลี่ยของจอบนต้องลดลงต่อเนื่อง
2. **0 ม.:** เห็นผิวน้ำชัด (สีฟ้าเทอร์ควอยซ์สดแบบ `[28,154,194]` + แถบท้องฟ้าขาว/แสงเลนส์ Snell ตามเดิม)
3. **ผ่าน 760 ม. (โซนกลาง):** ทไวไลต์ ฟ้าเข้ม · **1,976 ม. (โซนลึก):** มืดมาก · **3,040 ม.:** เกือบดำน้ำเงิน ใกล้ `[4,30,78]` (แถบท้องฟ้าหายไปจากจอแล้ว) · ค่าที่ต้องการโดยประมาณ (ยอมให้ปรับได้): ที่ 3,040 ม. ความสว่างเฉลี่ย R,G,B ≤ ~12,45,95 · ที่ 760 ม. ≈ 20,100,150 · ที่ 1,976 ม. ≈ 8,55,105
4. **แถบผิวน้ำเลื่อนหายขึ้นไปเมื่อดำลง** ภายในช่วง ~0–300 ม. (ทิศที่ถูก: ผิวน้ำเลื่อน **ออกจากจอทางด้านบน**) ไม่ใช่เลื่อนเข้ามา
5. ความมืดตามความลึกให้คิดจาก **ความลึกจริง (`state.depth`)** โดยตรงเป็นหลัก (แสงลดตามความลึก) ส่วนการเลื่อนของลวดลาย/กริด/คลื่นคงไว้ได้ ไม่ต้องให้ระยะเลื่อนครอบคลุม 3,040 ม. ทั้งช่วง
6. ปลา/สัตว์ 6 ตัวยังต้องปรากฏที่ความลึกที่ออกแบบไว้ใน `config/twin.json` (เทียบก่อน-หลัง: สแกนที่แต่ละความลึกแล้วต้องเจอตัวเดิม) · ตารางความลึกอ้างอิง (จากโมเดลเสียง): ฝูงปลาผิวน้ำ ≈ 0.03, ปลาแนวปะการัง ≈ 0.08, ม้าน้ำ ≈ 0.12, กระเบน ≈ 0.28, ปลาตะเกียง ≈ 0.40, แมงกะพรุน ≈ 0.75 (เป็นเลขทดสอบเสียงเท่านั้น ถ้า `twin.json` ต่างกัน ให้ยึด `twin.json` และรายงาน)

## 4. ข้อกำหนด

- **ห้ามแก้เฟิร์มแวร์** (`firmware/`), `config/scene.json`, `kAimWorld` · แก้ที่ twin และตั้งค่าเป็นค่าใน `config/twin.json` (เพิ่มคีย์ใหม่ได้ เช่น `depth_darkening`) · **บันทึกความต่างระหว่างภาพทวินกับเฟิร์มแวร์** ไว้ใน `output/luna-14-status.md` หัวข้อ "ต้องพอร์ตลงเฟิร์มแวร์" (เฟิร์มแวร์ยังใช้สูตรเดิมอยู่ จอจริงจะยังเป็นแบบเดิมจนกว่าจะมีใบพอร์ต) ห้ามแก้เองในใบนี้
- เทส/vectors เดิมที่ล็อกค่า `stripScrollMm` หรือภาพ (Python + Node + browser checks) **ห้ามลบหรือทำให้หย่อน** ถ้าต้องปรับ ให้แก้เทสให้ตรงสเปกใหม่พร้อมอธิบายเหตุผล และรันชุดเทสเต็มก่อนส่ง
- ห้ามแตะเรื่องเสียง (`twin.js` ส่วน audio) และ HUD/สไตล์ (เป็นงานของ LUNA-13) ยกเว้นที่จำเป็นจริง
- เพิ่มเทสอัตโนมัติ: ฟังก์ชันวัดความสว่างเฉลี่ยจอบนที่ depth = 0, 0.1, 0.25, 0.5, 0.75, 1.0 ต้อง **ลดลงทุกก้าว** และขอบเขตค่าตามข้อ 3

## 5. ปัญหา HUD ซ้อนกันที่เห็นในภาพเดียวกัน (ถ้า LUNA-13 B ยังไม่ครอบคลุม)

ที่หน้าต่าง ~1053×680: กล่อง "Deep Sphere Navigation" ซ้อนทับแถบความลึกกับตัวอักษร `0m / 760m`, ข้อความปุ่มลัด (`↑↓ depth …`) ตัดบรรทัดซ้อนกับแถบ, และเลข 3040 กับปุ่ม Explore/Scan ชิดกัน ให้ตรวจที่ 1053×680 และ 1366×768 แล้วแก้ให้ไม่ซ้อน (ใช้เลย์เอาต์ใหม่ของ LUNA-13 B ถ้าทำแล้ว)
